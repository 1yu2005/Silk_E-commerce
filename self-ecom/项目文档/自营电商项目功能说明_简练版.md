# 自营电商项目功能说明（简练版）

> 根据《自营电商项目功能说明_通俗版.md》整理。本文说明计划实现的功能，实际完成情况以开发验收为准。

## 一、项目定位

为一家自营店铺提供商品、库存、订单、发货和售后管理。**后台管理是重点，顾客端以完成购买和售后流程为主。** 支付、退款均为模拟操作，不发生真实资金交易。

## 二、岗位与权限

| 岗位 | 默认职责 |
|---|---|
| 超级管理员 | 拥有全部后台业务权限；管理员工、个人授权、全店设置、顾客账号限制、操作审计和疑难争议 |
| 商品与仓储 | 管分类、商品、价格和上下架；核实并登记库存；领取订单、拣货发货；验收退货；查看经营看板 |
| 客服 | 查订单与顾客资料；审核售后、要求补充材料、办理退款及失败重试；跟进发货和退货异常，记录沟通结果 |

- 员工账号由超级管理员创建并分配岗位，员工不自行注册；首个超级管理员由系统初始化。
- **员工实际权限＝固定岗位默认权限＋个人额外权限。** 个人授权只影响该员工，不改变岗位和同岗位其他员工。
- 超级管理员可增加或撤销个人额外权限；岗位默认权限不在个人设置中删减。调岗时清空原额外权限，再重新授权。
- 额外授权限于两个普通岗位的业务权限；员工与权限管理、全店设置、顾客账号限制、全店审计不下放。
- 菜单与操作按实际权限开放，权限变更从下一次操作请求起生效；所有人员均须遵守业务规则并留记录。

## 三、后台／商家端功能

| 模块 | 实现功能 | 默认负责岗位 |
|---|---|---|
| 员工管理 | 创建、停用账号，重置密码，分配岗位，调整个人额外权限 | 超级管理员 |
| 分类管理 | 最多三级分类，新增、修改、排序、删除；有子分类或商品时禁止删除 | 商品与仓储 |
| 商品管理 | 商品资料、品牌、图片、价格、成本、颜色尺码等款式；草稿、规格组合生成、批量填充、查询筛选、上下架及款式停用 | 商品与仓储 |
| 库存管理 | 初始库存、到货、损耗和更正登记；确认入账、库存预警及流水查询；退货可售数量回补 | 商品与仓储 |
| 订单管理 | 搜索筛选、商品与金额快照、收货信息、付款退款记录、物流、状态记录；客服内部备注 | 客服、商品与仓储按职责使用 |
| 发货管理 | 领取订单、拣货打包、交运确认、运单登记与修正、发货异常处理 | 商品与仓储；客服配合沟通 |
| 售后管理 | 申请审核、同意或拒绝、补充材料、退货物流、验收交接、整单退款及失败重试 | 客服主责；商品与仓储负责实物验收 |
| 顾客管理 | 查询资料、地址、订单与累计净消费；限制交易、冻结登录及恢复 | 客服查询；超级管理员管理账号状态 |
| 经营看板 | 支付、退款、净收款、订单、新顾客、待办、库存预警、销售趋势和热销商品 | 商品与仓储、超级管理员 |
| 全店设置 | 固定运费、满额包邮、退货地址、客户服务联系方式、处理期限 | 超级管理员 |
| 工作待办 | 当前经办人、任务领取、阶段交接、超期提醒和转交；员工停用或撤权后重新安排未完成任务 | 各岗位处理本职待办；超级管理员协调 |
| 操作审计 | 查询重要操作的人员、时间、原因及变更内容，历史记录不可随意修改删除 | 超级管理员 |

**库存登记规则：** 每次人工变动关联编号、原因和凭据，同一人可核实并确认入账；未确认不生效，已入账不重复执行，更正保留原记录。订单及售后引起的自动变动关联原业务单，不再人工重复入账。

**信息边界：** 商品与仓储可查看订单履约所需信息，默认不能查顾客完整资料或审核退款；客服默认不能修改商品库存、发货或验收实物。内部备注不向顾客展示，历史订单不随商品和地址资料修改而改变。

## 四、前台／顾客端功能

| 模块 | 实现功能 |
|---|---|
| 账号 | 手机号密码注册登录，修改昵称、头像和密码；首期不接短信验证 |
| 商品浏览 | 分类筛选、名称搜索、价格和销量排序；图片介绍、款式选择、对应价格与库存展示 |
| 购物车 | 加入商品、同款数量合并、改数量、勾选结算、删除和失效提示 |
| 收货地址 | 新增、编辑、删除、默认地址，最多20条 |
| 结算下单 | 选择地址、确认商品及运费、重新校验价格库存、提交订单、防重复建单 |
| 模拟支付 | 展示金额和付款倒计时、确认支付、查看结果 |
| 我的订单 | 按状态查看、查看详情与运单、取消未付款订单、确认收货 |
| 售后 | 申请整单售后、上传最多5张有效凭证、补充材料、查看审核结果、撤销未审核申请、填写退货物流、跟进退款 |

**不开发在线客服对话窗口。** 系统内通过售后表单、材料补充、状态及对外处理说明交互；需要直接联系时使用电话等系统外渠道，由客服记录结果。顾客在订单或售后详情查看更新。

## 五、核心业务流程

| 业务 | 流程 |
|---|---|
| 商品与到货 | 商品与仓储建立商品 → 核实数量并登记入账 → 完成资料及上架 |
| 正常购买 | 顾客浏览加购 → 确认地址与金额 → 下单留货 → 模拟支付 → 商品与仓储领取并发货 → 顾客确认收货 |
| 未付款取消 | 顾客取消、管理员关闭或超时关闭 → 释放占用库存 |
| 仅退款 | 顾客申请 → 客服审核并核实是否交运 → 按条件全额模拟退款；未交运只回补确认可售数量，已交运不自动回补 |
| 退货退款 | 顾客申请 → 客服同意 → 顾客寄回并填物流 → 商品与仓储验收、回补可售数量 → 客服全额模拟退款 |
| 缺货或发货异常 | 商品与仓储登记并暂停 → 客服确认等待补货或退款 → 核实实物与库存 → 解除异常发货或办理整单退款 |
| 退货验收异常 | 商品与仓储登记实收、照片及问题 → 客服核实或要求补寄 → 管理员协调争议 → 正常验收、批准异常全额退款或说明原因结案 |

## 六、必要业务规则

- **库存：** 下单减少可售量并增加待付款占用；支付后扣除占用，取消未付款订单则释放。购物车不留货，缺货不可下单，不得出现负库存或重复回补。
- **发货：** 一单一次整单发货、一个运单。填单号不等于交运；交运结果不明时先核实，不得直接按未发货退款。领取与处理记录防止多人重复打包。
- **售后：** 首期只支持整单全额仅退款或退货退款；未发货只能仅退款。进行中售后暂停发货及确认收货；退货仅回补验收可再次销售数量，异常批准不得虚填实收数量。
- **退款：** 审核通过不等于退款成功；失败保留原记录重试，同一业务不能重复退款。仅退款不要求实物验收，退货退款须完成验收或异常批准后的实收核实。
- **期限：** 默认30分钟未付关闭、正常发货满10天自动确认、确认收货后7天内申请常规售后。默认审核2个工作日、同意退货后7个自然日寄回、到货验收2个工作日、验收后退款1个工作日；超期进入跟进待办，不简单自动拒绝。
- **售后恢复：** 未退款结案只解除对应暂停；未发货恢复待处理，尚未收货的已发货订单恢复剩余收货时间并至少保留3天，已完成订单仍保持已完成；退款成功不恢复履约。
- **退货费用：** 普通无理由退货按项目规则全退订单实付，顾客承担寄回费用；质量、错发等由客服核实责任，额外费用线下协商留记录，不混入系统退款统计。
- **改址：** 未付款取消重下；已付款未交运先核实停止发货、整单退款后重下；已交运线下协商转寄。地址簿修改不改变旧订单。
- **账号限制：** 限制交易只阻止新下单，保留旧订单处理；冻结登录后由客服核实身份，代为记录旧订单售后及物流，不跳过原处理流程。
- **异常闭环：** 发货、退款、验收、库存更正及线下处理均记录原因、负责人和结果；无法解决的争议与无人接手待办由超级管理员协调。

## 七、首期范围

只做一家自营店铺、电脑端页面和模拟交易。不做多商家、多仓、真实支付、拆包或部分发货、部分退款、实时物流、在线聊天、小程序/App、优惠券和会员积分。补发、额外运费赔付及超期特殊售后仅保留线下处理记录，不提供对应自动交易功能。
