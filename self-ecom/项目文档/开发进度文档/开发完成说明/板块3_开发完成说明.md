增量迁移为`0003_files_communication_history`。开发库已经在前面的授权步骤应用；收尾没有重置数据库或改写已应用迁移。

| 表 | 保存什么 |
|---|---|
| `file_asset` | 文件用途、状态、公开性、尺寸/摘要、上传主体、存储键与到期时间 |
| `file_reference` | 哪个真实业务、哪个版本/槽位引用图片，以及允许谁看 |
| `communication` | 追加沟通、内部结果、顾客公开说明和更正关系 |
| `business_state_history` | 聚合状态变化、操作者和命令标识 |

已有`customer`增加`avatar_asset_id`外键；已有`audit_log`复用并扩展白名单，不另建第二套审计表。图片内容放磁盘/上传卷，数据库保存受控元数据与引用。

| 方法与路径 | 作用 |
|---|---|
| `POST /api/v1/files` | 登录后以multipart提交purpose和一个file，上传成功不等于业务绑定 |
| `GET /api/v1/files/{id}` | 有权者读取安全元数据 |
| `GET /api/v1/files/{id}/content` | 读取二进制图片；公开图可匿名，私有图须当前Bearer及业务权限 |
| `PUT /api/v1/store/me/avatar` | 以本人头像fileId设置当前头像 |
| `DELETE /api/v1/store/me/avatar` | 清空当前头像，保留历史文件 |

全项目现有27个OpenAPI操作，其中25个JSON调用器自动生成；上传和图片内容保留手写薄封装。沟通/状态历史及通用绑定目前是后端内部服务，没有允许浏览器随便绑定任意业务ID的接口。

## 4. 关键技术怎样支持功能

**图片确实能解码才接收。** busboy限制流量和multipart字段，sharp按魔数识别并完整解码、重编码，去掉EXIF等元数据。单图最多5MiB，宽高各10000、总像素4000万以内，拒绝动画、伪装和损坏图片。磁盘用随机键，拒绝路径穿越、链接及非普通文件，原文件名不会成为磁盘路径。

**上传和绑定分开。** 上传后是私有STAGED，固定24小时到期；业务确认时在事务内验证当前会话、用途、归属、到期及业务状态，建立引用并转RETAINED。头像指针、文件状态、引用和审计一起提交，任何一步失败整体回滚。更换头像只换当前指针，历史引用仍在。

**权限跟着当前业务走。** 私有图用Bearer读取Blob，token不进入图片URL；绑定后不能永久凭“我上传过”绕过业务授权。无权与不存在统一404，有权但磁盘内容丢失返回503。尚未建立的商品/订单/售后解析器默认拒绝，后续必须接入真实归属和权限。

**清理与绑定互相避让。** 数据库行锁、SKIP LOCKED和状态标记协调清理，已引用图片不会被到期任务误删；物理删除失败可重试。无数据库记录的孤儿文件使用48小时保守窗口。文件系统和数据库无法共同原子提交，所以另有失败补偿与孤儿扫描。

**记录和业务使用同一事务。** 沟通只追加，更正新增记录，旧记录保留；顾客投影只选公开说明和允许附件，内部结果与员工资料不透出。状态历史记录事实，不替领域执行发货或退款；写“退款成功”不能改变订单状态。

**契约减少前后端口径偏差。** 源码稳定导出OpenAPI，固定openapi-typescript7.13.0生成类型和调用器；工具内部用TypeScript5.9.3，工程保留6.0.3。`--check`发现源码、文档或生成文件不一致就失败。公共规范化和SHA256只提供命令指纹，真正的订单幂等落库、仲裁和结果重放留给板块8。

## 5. 启动、配置与复验

日常按[README本机启动](../../../README.md#本地启动)运行，不覆盖已有.env。已有环境先查迁移状态，不能盲目重新初始化。

```powershell
pnpm db:migrate:status
pnpm dev
# 顾客 http://localhost:5174/account
# 后台 http://localhost:5173
# Swagger http://localhost:3000/api/docs
```

文件默认位于`storage/uploads`；默认每主体20次/分钟、100张未绑定配额、300秒一次清理。`.env.example`中的`FILE_*`可调整这些运营参数，图片硬性安全上限不可通过环境变量放宽。Nginx请求体6MiB，容许合法图片的multipart开销；代理413使用32位十六进制requestId，API请求编号为UUID。

```powershell
pnpm openapi:export
pnpm api-client:generate
pnpm contracts:check
# 独立四服务完整复验，另需可用Docker及Playwright/Chromium
node infra/verify-auth-compose.mjs --files --output=output/playwright/新的验收目录
```

本轮独立容器已清理，**原8080/8081/3001容器没有被此次验收更新**。要把最新源码部署到常用Docker服务，另按README迁移/构建流程执行；本机查看头像不需要先更新旧容器。
