# 板块2 开发完成说明：登录、员工与权限

日期：2026-11-12。本期功能及四服务 Docker 验收通过，代码尚未提交。

## 1. 实现了什么

这一板块让系统知道：**谁在使用、账号能不能用、允许做哪些事。**

| 功能 | 已完成内容 |
|---|---|
| 员工登录 | 账号密码登录、刷新恢复、退出；首管理员无须首次改密，新建员工或重置密码后仍须改密 |
| 员工管理 | 查询、筛选、创建、修改显示名、启停、重置密码、调整岗位 |
| 权限管理 | 查看岗位默认权限和个人额外权限，为普通员工增减额外权限 |
| 顾客账号 | 手机号注册、登录、查看本人资料、修改昵称、改密和退出 |
| 操作记录 | 记录重要修改的操作者、原因和前后变化 |
| 两端页面 | 后台和商城均支持电脑、手机布局，处理登录失效、无权限和提交冲突 |

岗位固定为超级管理员、商品与仓储、客服，默认分别拥有52、25、12项权限。**最终权限＝岗位默认权限＋个人额外权限**，授权会自动处理依赖，管理员专属权限不能下放。

会话就是“一次登录的登记”：退出只结束当前会话；改密、重置密码或停用员工会结束该账号的全部会话。调整岗位或授权后，下次请求按最新权限检查；实际换岗会清空原有额外权限。系统也会阻止停用或降岗最后一位可用管理员。

## 3. 启动与使用

日常采用本机开发：数据库在Docker，后端和两个网站在本机。首次环境配置、迁移和管理员初始化见[README](../../../README.md)；准备完成后，在项目根目录执行：

```powershell
docker compose --env-file .env -f infra/compose.yaml up -d --wait db
pnpm dev
```

- 后台：<http://localhost:5173>，首管理员登录后可直接进入员工管理。
- 商城：<http://localhost:5174>，顾客注册后自行登录。
- 接口文档：<http://localhost:3000/api/docs>，需启用`SWAGGER_ENABLED`。

已有环境保留原`.env`和数据。四服务部署命令见[README部署部分](../../../README.md#四服务容器启动)。

### 管理员初始账号和密码

首管理员默认账号为`admin`、密码为`admin123`，创建后可直接登录，不要求首次改密。可通过根目录私有`.env`覆盖默认值；不配置时使用以下默认账号密码，显式空值仍会报错：

```dotenv
INIT_ADMIN_USERNAME=admin
INIT_ADMIN_PASSWORD=admin123
```

完成数据库迁移后，仅首次空员工库执行：

```powershell
pnpm db:seed:admin
```

员工由管理员创建，新建员工及重置密码后的员工仍必须改密。已有管理员时，重复seed不会覆盖其账号、密码或改密标志，也不能用于找回密码；这次代码调整不会自动重置数据库里的旧账号。

### 顾客如何注册

访问商城<http://localhost:5174/register>，填写手机号、密码、确认密码及可选昵称。手机号不能重复，注册成功后需要自行登录。

当前采用“手机号＋密码”注册，没有短信验证码，也未验证手机号归属。

### 忘记密码如何处理

| 情况 | 当前处理方式 |
|---|---|
| 普通员工忘记密码 | 管理员进入“员工管理→员工详情→重置密码”，设置临时密码并填写原因；员工用临时密码登录后必须改密 |
| 管理员忘记密码 | 由另一位可登录的超级管理员重置；不能通过该功能重置本人 |
| 唯一管理员忘记密码 | 当前没有恢复入口，需要补充专用运维恢复工具；初始化seed不能用于重置 |
| 顾客忘记密码 | 当前没有找回入口；现有“修改密码”必须登录并提供旧密码 |

员工密码重置后，全部旧登录会话立即失效。

顾客后续建议增加短信验证码找回：验证手机号归属→设置新密码→撤销全部旧会话→记录审计，并限制验证码有效期、尝试次数和发送频率。此流程尚未实现。

## 6. 关键技术

| 功能 | 使用的技术及作用 |
|---|---|
| 后端分工 | NestJS通过Module、Controller、Service、Guard分别组织依赖、接收请求、处理业务和检查访问资格，让不同职责分开 |
| 页面与路由 | React构建界面，React Router管理页面跳转，Ant Design提供表单和弹窗，CSS适配电脑和手机布局 |
| 数据保存 | PostgreSQL保存账号、会话、权限和审计等真实数据；Prisma负责数据库查询和表结构迁移，必要处结合数据库行锁 |
| 密码保存与校验 | bcrypt，cost=12，只保存哈希，登录时用compare核对。密码限制为8～64个Unicode字符、UTF-8最多72字节，保留首尾空格；前后端共用校验规则 |
| 登录凭证与会话 | jose签发和校验JWT，前端请求时携带凭证；后端同时核对数据库会话、账号状态和凭证版本，因此退出、停用和改密后可以立即使旧登录失效。默认有效期7200秒，过期后重新登录，没有refresh token接口 |
| 最新权限 | 三个固定岗位加个人额外授权，服务端自动处理权限依赖。每次受保护请求都读取当前身份和权限；JWT不保存岗位或权限快照，因此调岗、撤权后不必等旧凭证过期 |
| 并发与回滚 | 数据库事务保证关键修改和审计一起成功或一起失败；行锁保护相关账号及最后一位可用管理员；expectedVersion检查页面提交的资料版本，过时返回409，避免覆盖别人刚做的修改 |
| 严格输入 | class-validator、class-transformer配合DTO检查字段、格式和长度，拒绝未声明字段；前端提前提示输入问题，服务端仍独立校验 |
| 前端请求与凭证 | Axios统一发送请求和处理错误。员工与顾客凭证分开保存，仅持久化domain、accessToken、expiresAt；本人资料和权限保存在内存，恢复登录时重新向后端查询 |
| 异步状态 | React订阅控制器状态更新界面；请求取消和会话revision防止旧请求结果覆盖新登录或新查询目标。这里的前端状态版本与数据库资料版本用途不同 |
| 限流与排错 | 单实例内存限流限制密集登录、注册，并通过Retry-After提示等待时间；Pino脱敏日志、统一错误及requestId帮助关联请求、日志和审计，定位失败原因 |
| 接口与部署 | Swagger/OpenAPI描述请求、返回及错误契约；Docker Compose组织数据库、API、后台和商城四服务，Nginx提供静态页面及同源API转发 |

**权限最终由后端判断。** 前端隐藏按钮和拦截页面用于引导操作；账号被停用或权限被撤销后，旧页面和旧JWT也无法绕过后端检查，敏感写操作还会在数据库事务中重新核验操作者。

初始化工具称为seed，可以理解为“填入开店必需的固定资料”。权限seed重复执行不会重复插入；首管理员seed仅在员工表为空时创建账号。已有可用管理员时保留原账号；已有员工却没有可用管理员时明确失败，需要人工恢复，不会自动重置密码或启用旧账号。
