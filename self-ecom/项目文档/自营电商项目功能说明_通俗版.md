# 自营电商项目功能说明（通俗版）

> 编写日期：2026年11月10日  
> 依据：《自营电商系统需求文档 v1.1》  
> 本次修订：最终仅保留超级管理员、商品与仓储、客服三种岗位，统一个人授权、库存入账、履约和售后交接规则。本文为功能说明，不代表代码已实现；新增规则需落实到开发设计与验收中。  
> 阅读对象：项目负责人、商品与仓储人员、客服人员，以及不熟悉软件开发的读者。  
> 本文介绍项目按需求完成后应具备的功能，不是已经开发完成的证明；实际完成情况以演示和验收结果为准。

## 一、这个项目是做什么的？

这个项目是给**一家自己卖货的店铺**做一套网上经营工具。

它分成两个部分：

- **后台／商家端**：给店里的工作人员使用，用来管商品、管库存、处理订单、发货、处理退款，以及查看经营情况。这是项目的重点。
- **前台／顾客端**：给买东西的人使用，可以看商品、下单、模拟付款、确认收货和申请售后。页面保持简单，重点是把买卖流程走通。

可以把它理解成：前台是顾客看到的“网上货架和收银台”，后台是店员使用的“办公室和工作台”。两边用的是同一套商品、库存和订单信息，顾客下单后，工作人员就能在后台找到并处理。

这是==一家店自己卖商品的系统==，不是让很多商家入驻的淘宝式平台。

## 二、后台／商家端：工作人员可以做什么？

### 1. 管理员工，安排不同岗位的工作权限

**负责岗位：超级管理员。** 商品与仓储人员和客服人员使用自己的账号开展工作，默认都不能创建员工、修改岗位权限、停用其他员工或重置他人的密码。

店铺负责人可以给工作人员创建账号，安排他们负责的工作。员工用自己的账号登录，不需要大家共用一个管理员账号。



==超级管理员具备：==

- **后台所有业务权限**：可以执行商品与仓储人员和客服人员的操作，但同样必须遵守库存、退款和订单规则，操作也会留记录。
- **员工管理权限**：创建员工账号、停用账号、重置密码、分配或调整岗位和权限。
- **全店管理权限**：维护运费、退货地址，管理异常顾客账号，查看经营数据和全店操作记录。

新员工的加入流程是：**超级管理员创建账号 → 分配岗位和权限 → 员工使用该账号登录。** 员工不自行注册，也不需要提交注册申请。

另外，系统的**第一个超级管理员账号由初始化程序创建**；后续员工账号再由超级管理员管理。



==最终只设三种岗位：超级管理员、商品与仓储、客服==：

| 岗位 | 主要负责什么 | 默认不能做什么 |
|---|---|---|
| 超级管理员 | 创建和停用员工账号、重置密码、分配岗位及个人额外权限；维护全店设置；限制或冻结顾客账号；==查看全店经营数据和操作记录==；处理争议、转交待办并按规则接手业务 | 不能绕过库存、订单及退款规则，不能删除历史记录，也不能让系统失去最后一个可用的超级管理员 |
| 商品与仓储 | 管分类、商品资料、图片、价格、成本、款式和上下架；核实到货、登记并确认库存变更、设置库存提醒；领取订单、拣货打包、交运登记及运单修正；验收退货、记录可售数量；查看经营看板 | 默认不能审核售后、办理退款、管理顾客账号、管理员工和权限、修改全店设置或查询全店操作审计 |
| 客服 | 查询订单和顾客资料、联系顾客、写内部备注；审核售后、说明拒绝原因；跟进退货与发货异常；验收完成后办理模拟退款并处理失败重试 | 默认不能修改商品和库存、登记发货或验收实物退货，不能管理顾客账号、员工权限和全店设置，也不能查询全店操作审计 |

**三种岗位怎样配合：** ==商品与仓储负责“商品怎么卖、货有多少、货怎么发、退货收到什么”==，==客服负责“顾客沟通、售后是否同意、退款是否办完”==，==超级管理员负责“谁能做什么、全店规则和监督”==。

商品与仓储是一个岗位，可以安排一人，也可以安排多人。同岗位内部可以分工，但不再设置独立的运营岗或仓库岗，也不要求商品和实物处理之间增加一次跨岗位审批。日常到货入账允许同一人核实并确认，超级管理员通过记录核查异常；<u>退货验收与退款仍是两个不同业务步骤，默认由商品与仓储交接给客服完成。</u>

这里的“岗位”是员工的默认工作分工，不代表一定要招聘三个人。小店需要同一个人兼顾其它岗位的工作时，可以由超级管理员给这个员工单独增加相应权限，不需要修改原岗位的权限。线下拣货、打包和检查退货由工作人员实际完成，<u>系统负责登记过程和结果，不代替实物作业</u>。

日常业务由对应岗位处理；<u>超级管理员虽然能够接手全部模块，也必须遵守同样的校验规则，并留下自己的操作记录</u>。下面各模块按这套默认分工说明，特殊授权应另外明确，不能把“配合”理解成自动获得全部权限。



==**员工实际权限：固定岗位默认权限＋个人额外权限**==

**商品与仓储、客服两个普通岗位的默认权限，由超级管理员设定后保持固定。后续需要给某位员工增加工作内容时，只调整这名员工的个人额外权限，不修改岗位本身。**

==新员工由超级管理员创建账号，并指定所属岗位。员工最初获得该岗位的默认权限；若没有单独授权，就只能做该岗位允许的事情。员工不自行注册，也不需要提交注册申请==。

**员工实际权限＝所属岗位的固定默认权限＋超级管理员为该员工单独授予的额外权限。**

例如，小王和小李都是客服，初始都只有客服岗位的默认权限。后来小王需要临时兼顾发货，超级管理员可以只给小王增加“登记发货”和“修改运单”权限：

| 员工 | 所属岗位 | 个人额外权限 | 实际能做什么 |
|---|---|---|---|
| 小王 | 客服 | 登记发货、修改运单 | 客服岗位的全部默认工作，加上这两项发货工作 |
| 小李 | 客服 | 无 | 仍然只做客服岗位默认允许的工作 |

小王仍属于客服岗位，不会因为获得两项发货权限就自动拥有商品与仓储岗位的全部权限。其它客服员工不受影响，客服岗位本身也不发生变化。后续不再需要小王兼顾发货时，超级管理员撤销这两项个人额外权限，小王就恢复为客服岗位的默认权限。

后台在“员工管理”中提供“个人权限设置”，分开显示：

- **所属岗位及默认权限**：用于说明员工原本能做什么，不能在个人权限页面中取消。
- **个人额外权限**：由超级管理员单独勾选增加或撤销，按具体操作授权，不必一次开放另一个岗位的所有功能；所需的查询权限也要一并具备，例如登记发货需要能够查询对应订单。
- **最终实际权限**：合并显示这名员工当前能使用的功能，避免只看岗位名称而误判权限。

本设计不提供“单独禁止某项岗位默认权限”的设置。缩小权限指撤销个人额外权限；如果员工的基本职责发生变化，应调整所属岗位。更换岗位时，原个人额外权限先清空，再由超级管理员按新职责重新授予，避免旧授权被不知不觉地保留下来。

个人额外授权范围为商品与仓储、客服两个普通岗位的业务权限。==员工账号与权限管理、全店设置、顾客账号启停和全店操作审计等超级管理员专属权限，不通过普通员工的额外授权入口下放==；给员工增加业务权限也不会将其变成超级管理员。

每次调整都记录由哪位超级管理员操作、增加或撤销了什么权限、调整原因和时间，并从员工下一次操作请求起生效。员工已打开的页面不能继续执行被撤销的操作，系统会重新核验权限。

页面菜单和按钮也按员工的实际权限显示。给员工增加退货验收等操作权限时，必须同时具备查看相应业务单据的权限，避免“有按钮却看不到要处理的单据”。撤销权限不等于撤销此前已经成功办理的发货或退款。

兼岗员工可以按实际权限依次完成多个步骤，但不能跳过审核、实物验收等必要环节。记录始终显示实际操作人的账号，不把客服做的操作冒记成其他员工。本期不强制审核和退款由两个人完成，同一位有权限的客服可以办理，但每一步分别留记录。

后文各模块中的岗位分工均指默认安排。经过个人额外授权的员工，可以在实际授权范围内兼顾相应工作；未获授权的同岗位员工仍按原分工工作。所有员工即使获授权，也必须遵守相同的订单、库存和售后规则，并以本人账号留下操作记录。

员工离职或调岗时，可以停用账号或调整权限；调整后，原来的登录状态也不能继续使用已被收回的权限。系统会防止误操作导致所有管理员都被停用。

### 2. 整理商品分类，让货品更好找

**负责岗位：商品与仓储。** 负责分类新增、修改、排序和删除；超级管理员监督或接手，客服默认不维护分类。

工作人员可以==建立最多三级分类==，例如：

**服装 → 上衣 → T恤**

可以修改分类名称、显示顺序和图标。分类里还有商品，或者下面还有子分类时，不能直接删除，避免商品突然找不到归属。

顾客看到的分类会保留必要的上级入口，点击一个大分类，也能找到它下面小分类里的商品。

### 3. 录入商品，管理不同颜色和尺码

**负责岗位：商品与仓储。** 同一岗位负责商品资料、图片、销售价、成本价、款式、草稿、上下架，以及实物与初始数量核实，不再拆成两个岗位交接。超级管理员可监督或接手。

==商品与仓储人员可以录入商品名称、品牌、介绍、图片、分类等信息，并给同一商品设置不同款式。==

例如，一件T恤有黑色、白色，以及 S、M、L 三种尺码，就会形成六种可以买的组合。每一种组合都可以单独设置价格、成本、编号和库存。

后台可以自动生成这些组合，不需要工作人员逐条手工拼出来。新建商品时，还可以批量填写相同的价格或初始库存，减少重复操作。

初始库存须由商品与仓储人员按实物核实数量，注明对应凭据，并记录一次初始化入账；同一批货不能既算初始库存，又按新到货再加一次。商品建好后，库存变化走库存登记流程，不能通过编辑商品直接覆盖库存。

资料没填完，可以先存成草稿。准备上架时，系统再检查有没有主图、价格是否正确、商品是否有货等。资料不完整，不能直接上架给顾客购买。

工作人员还可以：

- 搜索商品，按分类、价格和销售状态筛选。
- 修改商品介绍和图片。
- 上架、下架，或批量上下架。
- 停用不再销售的款式。
- 查看各款式的价格和库存，以及整个商品的可售总量。

商品即使后来改名、改价或被移除，顾客过去买的订单仍显示当时的商品信息，不会跟着变。

### 4. 管理库存，知道还有多少能卖、为什么变了

**负责岗位：商品与仓储。** 统一负责核实实物、登记初始库存、到货与损耗入账、设置库存提醒和查询变动记录。超级管理员负责异常核查，并可接手处理；客服默认不能修改库存。

**到货和损耗仍要有“库存变更登记”，但不再要求两个岗位审批。** 商品与仓储人员核实商品款式、数量，填写原因及凭据，保存后再次确认入账；同一名员工可以完成这两个步骤。若由同岗位另一名员工接手，需先领取并显示当前经办人，避免重复登记或入账。

每张登记有唯一编号及“待确认、已入账、已作废”状态。待确认只保存资料，不影响库存；有权限的经办人核对后确认，系统一次性更新库存并生成记录。不再需要的登记填写原因后作废；已入账登记不能作废、修改或重复入账，录错需引用原编号另做更正登记。相同来源凭据及商品明细须关联校验，避免换个登记编号重复计入同一批货。超级管理员可核查异常、接手或要求更正，但日常入账不必等待其审批。

同一来源分批到货时，分别登记实际到货批次与数量，不能简单禁止整张送货凭据再次使用。系统校验来源明细的已入账数量及本次批次，防止重复；更正记录保留原单关联。没有外部单号的损耗也须上传说明或照片，生成内部登记编号。

退货是一个单独入口：商品与仓储人员完成整单验收，或经批准完成异常退货结案的最终核实后，系统才把其中可重新销售的数量一次性加回库存，任何员工都不能再为同一批退货手工加一次。仅保存实收草稿或验收异常，不触发回补。下单占用、付款扣减、取消释放和未发货退款回补也由系统按规则处理，不需要岗位人员另行补数。

==后台会把库存分成两种==：

- **可售库存**：现在还能卖给其他顾客的数量。
- **待付款占用库存**：顾客已经下单、暂时替他留住，但还没有付款的数量。

例如，一款T恤有10件可卖，有人下单买2件但还没付款，系统就显示“可售8件，待付款占用2件”。这样其他顾客不会再把这2件买走。

如果付款成功，这2件就算分配给这笔订单；如果顾客取消或超过付款时间，2件会重新变成可售库存。

商品与仓储人员或超级管理员可以手工增加或减少可售库存，但必须填写原因，例如“新到货20件”或“发现破损1件”；不能直接改动待付款占用数量。系统会记录谁改的、什么时候改的、改之前和之后分别是多少。

每种款式还可以设置库存提醒线，默认是10件。剩余可售数量达到或低于提醒线时，后台会标出来，方便安排补货。

**这部分重点是==防止卖出超过可售数量的商品，并让每次变化都能查到原因==。它不代替完整的仓库盘点系统。**

### 5. 集中处理订单和发货

**订单查询、顾客沟通和内部备注由客服人员负责；拣货、打包、登记发货和修改运单由商品与仓储人员负责。** 超级管理员可监督、接手，并处理需要手动关闭的未付款订单；默认客服和商品与仓储人员都不能手动关闭未付款订单，已付款订单则一律走售后退款。商品与仓储人员可以查看履约所需订单、收货及暂停信息，但默认不能编辑客服内部备注、审核售后或退款。

顾客下单后，工作人员可以在后台看到订单，并按订单号、收货人、手机号、状态和下单时间查找。

一笔订单的详情里，可以看到：

- 顾客买了什么、每件多少钱、买了多少件。
- 商品金额、运费、实际付款金额。
- 收货人、电话和地址。
- 付款记录、退款记录。
- 发货物流公司和运单号。
- 从下单到完成的处理过程。
- 仅供店内人员查看的内部备注。

商品与仓储人员可以在“待发货”列表中找到需要处理的订单，确认无进行中的售后后，填好物流公司和运单号登记发货。首期是一笔订单一次性发完，使用一个运单，不把一笔订单拆成多个包裹管理。

具体工作顺序是：**待处理 → 商品与仓储人员领取 → 拣货打包 → 确认交运并登记发货**。商品与仓储人员领取后，订单标为“备货处理中”，显示当前经办人，避免另一个人重复打包。“备货处理中”是后台工作进度，顾客侧仍显示待发货；售后或发货异常是附加提示，不与订单状态混在一起。

填了运单号只算准备好，不能自动代表已经交给快递。实际交接时应先核对系统允许发货、无暂停事项，锁定本次交运动作，再把包裹交出并立即完成登记。交运处理中暂不允许直接完成未发货退款；顾客此时提出售后，先登记待核实，由商品与仓储人员确认实际交接结果，再由客服按未发货或已发货规则处理。页面操作失败但包裹已交出的，要标为“交运结果待核实”，不能当作货还在仓库。

如果商品与仓储人员已领取但还没有交出包裹，收到售后或改址请求，应暂停拣货与交运；商品与仓储人员确认货仍在手里、没有交出后，客服才能按未发货情况处理。系统可以防止两个人同时登记，但无法自己看到实物，商品与仓储人员必须如实确认。不能把缺少物流登记当作包裹一定未发出的证据。

**发现缺货、破损或款式不符时**，商品与仓储人员登记“发货异常”、原因和照片，暂停发货；客服领取沟通待办，确认顾客选择等待补货还是整单退款；商品与仓储人员核实并记录库存差异；补齐后由其确认实物已齐，客服登记顾客仍同意继续履约，双方事项均解除后才可继续发货。决定退款时由客服记录顾客同意，并创建整单售后交由有权限人员处理。首期不支持部分发货、部分退款，不能擅自少发。

运单填错可由商品与仓储人员填写原因后修正，保留原单号、新单号和操作人。订单完成或退款后，普通商品与仓储人员不能继续修改；确需纠正历史信息，由超级管理员记录原因处理。实际补发、重新寄送不是单号填错，首期只支持客服记录线下处理及关联运单，不提供补发订单和自动库存处理，不能覆盖原发货记录来冒充一次发货。顾客能看到自己的运单信息，不能看到店内内部备注。

**顾客地址填错怎么办？** 首期不提供订单内直接改址，以免与拣货交接冲突。未付款可取消重下；已付款未交运则先暂停，商品与仓储人员确认未交出并撤回拣货后，由客服协助整单退款，顾客用新地址重新下单；已交快递只能由客服线下协商转寄并记录结果。修改地址簿不会修改旧订单，工作人员不得只改地址簿就告诉顾客改址成功。

==订单默认有30分钟付款时间，超时未付会自动关闭，并释放占用库存==。已经付款的订单不能直接当作未付款订单关闭，必须走退款流程。

### 6. 处理退款、退货，并防止重复操作

**售后主责岗位：客服；实物退货验收负责岗位：商品与仓储。** 客服查看申请和凭证、同意或拒绝、办理模拟退款并跟进失败；商品与仓储人员核对退回数量和品相、记录异常及可重新销售数量，默认不能决定是否同意售后或办理退款。超级管理员处理争议或接手。

**首期不开发客服与顾客的在线对话窗口。** “客服”是负责审核和处理售后的员工岗位，不代表系统必须有实时聊天。顾客通过售后申请表提交问题，客服在后台审核，双方通过同一张售后单的状态、处理说明和材料补充表单完成必要交互。

基本流程是：**顾客提交申请 → 客服审核 → 顾客查看结果 → 按审核结果继续退款或退货**。客服可以同意、填写原因拒绝，或要求顾客补充材料；需要退货的，审核通过后展示退货地址，顾客填写寄回物流，商品与仓储人员验收后再由客服办理模拟退款。

要求补充材料时，售后单显示“待顾客补充”，客服填写具体要求；顾客在原售后单中补充文字或凭证，提交后返回待审核，不另建重复申请。保留每次要求与提交的记录，期间仍按进行中售后暂停相关履约。默认补充期限为7个自然日，超时进入客服跟进待办，不直接自动拒绝；确需结束须说明原因，有争议交管理员处理。补充后按新的待审核时间重新计算审核期限，历史逾期记录仍保留。

顾客能看到审核结果、需补材料、退货地址、物流填写入口、退款进度及对外处理说明；店内备注、内部讨论和员工个人信息不对顾客展示。首期通过刷新或重新进入订单、售后详情查看更新，不要求聊天式即时提醒、消息已读或在线状态。

全文中“联系客服”“联系顾客”“沟通”“提醒”等需要直接联系的行为，首期均指电话等系统外渠道，不表示系统内有聊天、短信或电话拨打功能。店铺提供固定的客户服务联系方式，由超级管理员维护并在顾客端展示；员工在有权处理的业务单中记录联系时间、渠道、结果、下一步和必要凭据，不上传无关个人信息。联系不上时按原有超期、转交或争议规则处理，不能因为没有聊天窗口就跳过必要确认。

客服的职责不止审核：同意后仍需跟进退货、验收异常、退款和失败重试，直到售后结束。首期不做实时聊天、聊天记录、聊天图片发送、已读状态或在线坐席管理；材料图片只作为售后凭证提交。

具体交接是：仅退款由客服审核通过后办理退款，其中商品与仓储人员已开始处理的订单须先核实是否实际交运；退货退款由客服先同意退货，商品与仓储人员收到全部退货并完成验收，再交给客服办理退款。默认客服没有验收权限；获得个人额外授权的员工，只有实际完成实物检查才能登记验收，不能仅凭顾客说已寄回或凭证照片确认收货。商品与仓储人员也不能把“验收完成”当成“退款完成”。

首期售后按**整笔订单、全额退款**处理。不能只退订单里的某一件，也不能只退一部分钱。

分为两种情况：

| 售后方式 | 怎么处理 |
|---|---|
| 仅退款 | 顾客提出申请，客服审核；同意后办理全额模拟退款，不要求顾客寄回商品 |
| 退货退款 | 客服同意退货，顾客填写寄回物流，商品与仓储人员收到并验收全部商品后，再办理全额模拟退款 |

未发货的订单，只能申请仅退款。已经发货或收货的订单，可以根据实际情况申请仅退款或退货退款。确认收货后，申请期限为7天；此前已提交的申请不会因为超过7天就突然失效。

7天是本项目普通商品的常规在线申请期限，不代表超过7天就没有任何售后责任。超期质量问题、错发等由客服登记线下售后工单，超级管理员协调处理。首期不新增部分退款、补发或赔付付款功能，但须保留诉求、处理决定、线下结果及凭据；不能把线下记录计成系统内已退款。

客服可以查看申请原因、说明和凭证图片。同意、拒绝、退款失败后的重试，都会留下记录；拒绝时必须写原因。

退货到仓后，商品与仓储人员需要登记实际收到多少、其中多少还能重新销售。能重新销售的才加回可售库存，破损商品不会直接当成好货重新上架。

收到少件、错货、空包等时，商品与仓储人员先保存实收数量、照片和“验收异常”，不能直接确认整单验收成功。客服联系顾客补寄或核实；数量补齐且核对无误后，商品与仓储人员再完成验收。需要拒绝或结束申请时，由客服提出处理意见，超级管理员核对实物去向、证据和沟通结果后确认关闭，并向顾客说明原因，不能以“线下协调”长期搁置。

未完成整单验收前，本期不自动将部分退回商品加回可售库存；暂存货物单独保管。异常结案涉及退回商品由谁保管、是否寄还顾客，必须记录；若获准不齐货全额退款，使用“异常退款批准”记录，并由商品与仓储人员先最终确认已收货物与可售数量，再回补一次，由客服全额退款。此例外不允许部分金额退款，也不能虚填成全部收到。因商品原本有质量问题而无法再次销售，不应仅凭“不能再卖”就拒绝退款。

本期默认普通无理由整单退款退还原订单实付（含原运费），顾客承担寄回费用；质量问题、商家错发等责任由客服核实并记录，不能一律要求顾客承担退货运费。首期额外运费赔付仅记录线下协商和支付凭据，不走系统模拟退款金额，也不混入系统退款统计。

**售后有处理期限和超期待办。** 默认客服在申请后2个工作日内处理；同意退货后，顾客应在7个自然日内实际寄出并填写物流。超时先进入客服提醒列表，不直接自动拒绝。仅填写单号不等于实际寄出；客服核实提醒后，确认未寄回才可填写原因关闭申请，有寄出凭据或仍在运输中的不能仅凭超时关闭。商品与仓储人员实际收到包裹后应在2个工作日内登记验收或异常，验收完成后客服在1个工作日内办理退款或登记失败原因。

期限由超级管理员统一设置并在单据中保存当时的截止时间；工作日按周一至周五计算，首期不接节假日调休日历。确有特殊情况可由超级管理员填写原因延期，不能仅靠改全局设置隐藏已超期记录。系统不接实时物流，由客服人工核实物流、寄出和签收凭据。

售后被拒绝、撤销或关闭后，系统解除对应暂停，但有其它未解除异常的订单仍不能发货。未发货订单退回商品与仓储待处理列表，不自动交运；已发货订单恢复确认收货，自动确认按申请售后时剩余时间继续计时，并至少再留3个自然日给顾客核实。顾客主动确认收货仍须确认没有进行中售后；退款成功的订单不会恢复发货或自动收货。

**每一步都要在对应岗位的待办中出现：**

| 待办事项 | 默认由谁领取处理 | 交给谁、何时结束 |
|---|---|---|
| 待审核售后、待跟进寄回 | 客服 | 同意后等待退货，拒绝或撤销则按规则结束 |
| 待到货、待验收、验收异常 | 商品与仓储；客服配合沟通 | 验收完成进入客服待退款，争议转管理员 |
| 待退款、退款失败 | 客服 | 成功后结束；失败保留待办，沿用原退款记录重试 |
| 发货异常、顾客改址诉求 | 商品与仓储确认实物及库存，客服沟通 | 解除异常继续履约，或完成整单退款 |
| 超期未处理、无法解决的争议 | 当前经办人跟进，超级管理员协调 | 明确下一负责人、处理期限和结果 |

订单发货和售后单均显示当前经办人，领取后才处理；系统保证同一工作环节只有一人领取，客服和商品与仓储的不同环节分别交接。超级管理员可转交，经办人离职、停用或权限被收回时，未完成待办退回相应岗位列表并提示管理员重新安排。领取不是永久独占查看，也不能绕过权限或状态限制。首期用待办列表、数量提醒和处理记录实现，不要求短信、聊天或复杂审批系统。

系统还会限制一些容易出错的操作：

- 一笔订单同时只能有一个正在处理的售后。
- 售后处理期间不能继续发货或确认收货。
- 同一次退款重复点击，不会重复退款。
- 同一批退货重复确认，不会重复增加库存。
- 已经发货但同意“不退货只退款”，不会凭空把商品加回库存。

后台会清楚区分“审核通过”和“退款成功”，避免客服以为钱已经退了，实际上还停在中间步骤。

### 7. 查看顾客资料和购买记录

**日常负责岗位：客服人员；顾客账号启用、停用由超级管理员负责。** 客服按工作需要查资料、查历史购买情况，发现异常后向超级管理员反馈，默认无权停用账号。商品与仓储人员可在有权查看的订单中读取履约所需收货信息，但默认不能查看顾客管理页面、完整地址簿或全部个人资料。

有权限的工作人员可以查找顾客，查看注册时间、最近登录时间、订单记录、地址和累计净消费。

这里的累计净消费，会考虑已经完成的订单以及后来发生的退款，不是只把付款金额一直往上加。

对于异常账号，超级管理员可以“限制交易”：禁止新下单，但保留登录、查看旧订单、付款期限内支付已有订单、确认收货和处理已有订单售后的能力。若需阻止某笔旧订单付款，应另外按订单关闭规则处理，不把账号限制当作取消订单。

严重异常可“冻结登录”，顾客不能继续登录操作，但历史订单和售后仍有效。客服通过核实身份的线下渠道受理诉求，代为登记关联原订单的售后、退货物流和凭证，并注明信息来源和操作人；不能绕过审核、验收和退款步骤。恢复权限由超级管理员操作，所有限制、冻结和恢复都有原因与记录。

### 8. 查看店铺经营情况

**日常负责岗位：商品与仓储；监督岗位：超级管理员。** 商品与仓储人员查看销售趋势、热销商品和库存预警，安排商品上下架、补货和日常发货；超级管理员关注整体经营与异常。客服默认不看全店经营看板，在订单和售后列表处理自己的待办。

后台有一个简单的经营看板，帮助负责人快速了解：

- 今天收到多少订单、增加多少顾客。
- 今天支付了多少钱、退了多少钱、两者相减后是多少。
- 还有多少订单需要发货，多少订单因售后暂时不能发货。
- 有多少售后等待审核、多少退款失败需要处理。
- 哪些款式库存偏低。
- 最近7天或30天的变化趋势。
- 最近30天哪些商品支付销量较高。

“今天收的钱”和“今天退的钱”分别显示。例如今天退的是上周订单的钱，也会算作今天的退款，不会混在一起让人误以为今天没有发生退款。

### 9. 设置运费和退货地址

**负责岗位：超级管理员。** 商品与仓储人员提出运费建议，并核实退货地址及联系人；客服向顾客解释规则、反馈问题。两个普通岗位默认都不能修改全店设置，由超级管理员确认并录入。

负责人可以设置全店统一的固定运费和包邮门槛。例如：商品金额满99元包邮，不满收10元。

首期不按省份、重量等分别算运费，也不让不同商品使用不同运费规则。

后台还可以维护商家的退货地址。同意顾客退货时，会保存当时提供的地址；以后改了退货地址，不会让正在退货的顾客突然找不到原地址。

### 10. 查询重要操作，出现问题有据可查

**负责岗位：超级管理员。** 负责查询全店操作记录、核对异常和追查原因。商品与仓储和客服默认不能查询全店操作审计，但可以在有权限的业务页面查看相关记录：商品与仓储查看库存、发货和退货验收记录，客服查看订单沟通和售后处理记录；这些记录都不能随意更改。

系统会记录重要操作，例如谁改了库存、谁发了货、谁同意退款、谁修改了员工权限。

负责人可以按人员、业务类型、单号和时间查找，知道事情是怎么发生的。这些记录不能像普通商品资料一样随意修改或删除。

密码和登录凭证不会写进这些记录，顾客的联系方式等信息也会按使用场景进行遮挡。

## 三、前台／顾客端：买东西的人可以做什么？

### 1. 注册、登录和修改个人资料

顾客可以使用手机号和密码注册、登录，修改昵称、头像和密码。购物车、地址、订单等个人页面需要登录后才能使用。

本期不接短信验证码，所以这套手机号注册方式主要用于项目演示，不能据此认定手机号已经由本人验证。

### 2. 看商品，选择喜欢的款式

顾客可以浏览商品，按分类找商品、输入名称搜索，也可以按价格或累计销量排序。

进入详情后，可以看图片和介绍，选择颜色、尺码等款式，再看到对应的价格和剩余可售数量。没有库存时，不能继续购买；商品下架后，也不能再新买。

页面只提供基本的商品展示，不做复杂首页、促销专区或花哨装修。

### 3. 使用购物车

顾客可以把商品加入购物车，修改数量、删除商品、勾选要一起结算的商品。同一种款式重复加入，会合并数量。

放进购物车不代表已经替顾客留货。如果之后库存不足或商品下架，购物车会说明原因，不能按原样直接结算。

### 4. 管理收货地址

顾客可以新增、编辑、删除收货地址，并选一个默认地址，最多保存20条。

下单时可以选择其他地址。以后修改或删除地址，不会改掉已经提交订单上的收货信息。

### 5. 确认价格、运费并提交订单

结算页展示商品清单、数量、地址、运费和最终合计，顾客确认后提交订单。

提交时会再次检查商品是否还能买、库存够不够、价格和运费有没有变化。如果价格变化，会让顾客重新确认，不会不声不响地按更高价格下单。

提交成功后，购买的数量会从购物车中扣掉，并暂时占用相应库存。重复点击或网络重试，会尽量返回同一笔订单，避免多生成订单。

### 6. 进行模拟付款

顾客可以在付款页看订单金额和剩余付款时间，再点击“模拟支付”。成功后，订单进入待发货，后台工作人员就可以继续处理。

**模拟支付不扣银行卡余额，也不通过微信或支付宝转钱。退款同样是模拟记录，不会真的把钱打到账户。**

顾客暂时不付，可以返回订单列表，在付款期限内再付；超过期限则不能继续付款，需要重新购买。

### 7. 查看订单和确认收货

顾客可以查看待付款、待发货、已发货、已完成、已关闭及退款订单，也能单独找到售后中的订单。

未付款时可以取消。商家发货后，可以看到物流公司和运单号；本期不提供包裹位置、预计送达时间等实时物流查询。

收到商品后可以确认收货。如果没有进行中的售后，发货满10天会自动确认收货。

有售后或交运待核实等暂停事项时，会显示原因，不能继续按普通流程发货或自动收货；售后未退款结案后，按后台说明恢复剩余收货时间，并至少保留3个自然日，不会刚结案就立刻自动确认收货。

### 8. 申请售后并跟进结果

顾客可以选择允许的售后类型，填写原因和说明，上传最多5张凭证图，并查看处理进度。

这里不设置在线客服聊天窗口。顾客提交申请后，在售后详情查看客服的审核结果与对外说明；收到补充要求时，在原申请中补充文字或凭证，再提交审核。补充凭证后整张售后单有效图片总数仍不超过5张，可替换当前图片，历史提交记录保留；客服意见和材料记录按处理步骤展示，不做自由对话框。需要进一步沟通时，使用页面展示的客户服务联系方式，通过电话等系统外渠道联系。

申请尚未审核时可以撤销。退货申请通过后，顾客能看到商家的退货地址，寄出后填写物流公司和运单号；商品与仓储人员验收后，后台办理模拟退款。

首期只处理整单全额售后，退款金额由订单决定，顾客不能自行改成部分金额。普通无理由退货的寄回费用由顾客承担；质量问题、错发等由客服核实责任并线下协商，额外运费处理结果会留记录，但系统不自动报销。顾客可以看到需补充的材料、验收异常及申请结束原因；同意退货后默认7个自然日内实际寄出并填写物流，特殊情况及时联系客户服务人员。

## 四、两边怎样配合？用一笔订单说明

假设店铺卖一件黑色L码T恤：

1. **商品与仓储人员上货**：后台填商品资料、价格、图片和库存，检查通过后上架。
2. **顾客购买**：前台找到商品，选黑色L码，放入购物车，填写地址并提交订单。
3. **系统留货**：暂时占用购买数量，避免同一件库存卖给多个人。
4. **顾客模拟付款**：付款成功，后台订单进入待发货。
5. **商品与仓储人员发货**：领取订单，核对并拣货打包，确认没有售后或发货异常，在实际交运时完成登记；顾客前台看到发货和运单信息。
6. **顾客收货**：确认收货后，订单完成。
7. **需要售后时**：顾客在期限内申请整单退货退款；客服审核，顾客寄回，商品与仓储人员验收并登记可重新销售的数量，系统据此回补库存，再由客服办理模拟退款。
8. **超级管理员查记录**：能看到这笔订单的付款、发货、退货、退款和库存变化过程，核对各岗位是否按分工处理。

如果顾客在付款前取消，系统释放占用库存；如果付款后还没发货就获准整单退款，系统退回模拟款项，并把确认仍可销售的数量恢复为可售。正常情况下恢复订单的全部数量，存在已核实损耗时按实际数量处理。不同情况按不同规则处理。

如果已经进入仓库处理或交运环节，必须先查清货物在哪里，再决定退款与库存处理。若货物缺失或损坏，不能把它当作仍可销售的商品恢复库存；商品与仓储人员登记异常，并关联原订单核实损耗，系统按实际可重新销售量处理回补，其余保留损耗记录，避免退款后把找不到的货再次卖出。

损耗登记需区分“来自可售库存”还是“来自已付款订单的备货”。前者由商品与仓储人员确认登记后扣减可售数量；后者在付款时已从可售范围扣除，仅记录损耗和减少退款时的回补量，不能再扣一次可售库存。存在待付款占用且实物不足时，先暂停对应款式新增购买，由商品与仓储人员核实受影响库存、客服跟进相应订单，按取消释放与关联损耗登记一起处理，不允许直接修改占用数量或释放后把已损坏的货变成可售。

四条主要工作链为，其中到货入账在商品与仓储岗位内完成，售后沟通与退款仍需跨岗位配合：

| 工作 | 交接顺序 |
|---|---|
| 到货或损耗 | 商品与仓储人员核实实物 → 填写并确认登记（可同一人完成） → 系统入账一次 → 管理员可核查 |
| 正常发货 | 商品与仓储人员领取 → 拣货打包 → 核对允许交运 → 实际交接并登记 |
| 缺货或发货异常 | 商品与仓储暂停并核实库存 → 客服联系顾客 → 双方完成各自待办 → 恢复发货或整单退款 |
| 退货退款 | 客服审核 → 顾客寄回 → 商品与仓储人员验收或登记异常 → 客服退款 → 管理员协调疑难情况 |

## 五、这期项目做到哪里、不做到哪里？

| 这期包含 | 这期不包含 |
|---|---|
| 一家自营店铺的后台经营管理 | 多商家入驻、商家抽佣和分账 |
| 普通实物商品及颜色尺码等不同款式 | 多仓调拨、完整仓库盘点体系 |
| 简单电脑端购物页面 | 手机小程序、App、复杂页面装修 |
| 模拟支付和模拟退款 | 微信、支付宝、银行卡真实收付款 |
| 一单一个运单的发货登记 | 拆包发货、电子面单、实时物流跟踪 |
| 整单全额退款、整单退货退款 | 只退某件商品、部分数量或部分金额 |
| 固定运费和满额包邮 | 按地区、重量计算复杂运费 |
| 基础经营看板和操作记录 | 优惠券、秒杀、积分、会员等级等营销玩法 |
| 售后申请、审核结果、对外说明及材料补充表单 | 在线客服对话窗口、实时聊天、已读状态、在线坐席和系统自动短信通知 |

这份项目的重点，是让店铺工作人员能够**把商品管清楚、把订单处理完整、把库存和退款算准确、出了问题能查到过程**。顾客端保持简单，但要能配合后台完整演示从购买到售后的全过程。

## 六、怎样保证这些流程能开发出来？

新增流程以少量登记表、状态、操作权限和待办列表实现，不增加采购系统、完整仓储系统或实时物流平台。开发时至少遵守以下规则：

- 订单的付款、发货、完成、关闭、退款，与备货工作进度、暂停原因、售后进度分别记录，页面组合展示，避免所有情况硬塞成一个订单状态。
- 业务经办人由系统领取操作确定，不能只在备注里写名字；领取、转交、退回列表和超期都能查到过程。
- 先由服务器检查实际权限、当前业务状态及必要凭据，再执行操作；按钮隐藏不能替代检查。
- 多人同时领取、发货、退款或入账时，只允许符合条件的一次操作成功；库存变动和对应业务记录一起保存，失败时不能只保存一半。
- 到货登记、退货回补、取消释放及退款都有对应唯一单号和处理结果，重复点击、网络重试或重复交接不能重复增加库存或退款。
- 拒绝、关闭、纠正和线下处理都有原因及记录；冻结账号、授权变化及员工离职不会让待办无人接手。

验收时除正常购物流程外，还应演示：两人抢同一订单领取、备货处理中申请退款、包裹交出但登记失败、到货重复入账、退货少件补寄、验收异常批准退款、退款失败后重试、顾客超期未寄回、员工权限撤销后待办转交。这些场景通过后，才能说明岗位之间的协作流程真正走通。
