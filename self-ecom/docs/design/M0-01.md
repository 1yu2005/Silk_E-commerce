## 结构与工具

- 当前根目录直接作为 monorepo，不增加 shop 层；包名使用 @shop/*。
- Node 24.18.0、pnpm 11.25.0；所有直接 npm 依赖固定完整版本。
- NestJS 12.4.2、React 19.3.1、Vite 8.3.8、Ant Design 6.7.0。
- TypeScript 6.0.3 同时满足 Swagger 与 ESLint 工具链范围。Vite React 插件使用兼容 Vite 8 的 5.2.0。
- 公共包编译至 dist，Turbo 通过 ^build 明确构建依赖；dev 持久运行不缓存，test 不缓存。
- ESLint 平面配置共用；TypeScript strict，开启索引访问检查。
- API 初始无业务表、无业务路由。不得加入假登录、假用户、假商品表。
- Prisma使用7.10.1的CLI/client/adapter-pg，配置文件声明datasource URL，schema不含业务模型；已验证空模型客户端生成和真实查询。迁移命令由受控脚本读取环境配置。

## 后续接口与部署决策

DTO基础已实现全局ValidationPipe：whitelist、forbidNonWhitelisted、transform及禁止隐式类型转换。分页公共DTO默认page=1、pageSize=20，pageSize最大100；数字字符串仅显式转换为安全整数，布尔字符串仅接受true/false。错误details为field/message数组，使用固定消息，不回传输入值、校验对象或任意异常内容。测试控制器只注册于测试模块，未发布业务接口；后续控制器必须声明DTO类才能应用字段规则。

- API 前缀 /api/v1，两站代理保留 /api；Swagger 原生 HTML/JSON 不套成功外壳。
- Swagger已实现：开关控制/api/docs与/api/docs-json，servers为相对根路径/，paths包含完整/api/v1；显式声明健康接口200/503模型、UTC时间、请求编号响应头与稳定operationId。离线导出不执行app.init/listen，避免依赖数据库可达性；不注册测试控制器。不启用YAML入口或预置Bearer鉴权。
- 请求 UUID、成功/错误响应、严格 DTO、脱敏日志由公共基础层集中处理。
- live 不依赖数据库，ready 用有界超时 SELECT 1；迁移状态单独检查。
- PostgreSQL 16，0001_bootstrap 仅初始化 schema；不提前创建员工或商品表。
- 集成测试必须使用不同于开发库的独立测试库，先验证目标再执行可能修改数据的操作。
- 四个长期服务为 db/api/admin-web/store-web；迁移独立执行，不在启动时重置数据库。
- 容器API以Node非root用户运行，运行镜像保留Prisma CLI及tsx用于统一包脚本执行一次性migrate deploy/status；关闭pnpm运行脚本前自动安装，避免生产依赖部署后误触发重装。构建时生成Linux Prisma客户端并随生产依赖部署。前端多阶段构建后只交付Nginx与dist，真实.env和宿主node_modules不进入构建上下文；index不长期缓存，哈希静态资源使用immutable缓存。
- Compose默认端口API3000、后台8080、顾客8081。本机API_HOST_PORT=3001避开仍在运行的开发API；CORS使用独立COMPOSE_CORS_ORIGINS，容器内数据库连接使用db:5432。现有数据库卷复用，另加uploads卷，Nginx不挂载上传目录。
- 数据与上传目录持久化，上传卷不直接静态公开；登录、上传业务属于后续板块。

## 环境记录

### 请求日志实现

使用nestjs-pino/Pino，通过配置工厂读取LOG_LEVEL；Nest启动日志也接入同一日志器。请求ID存于WeakMap，由公共中间件和Pino共享，忽略客户端传入编号。HTTP序列化采用白名单，仅保留方法、去查询参数的路径、状态码，另记录requestId及耗时；错误仅输出固定类型，避免携带连接串或SQL。常见敏感字段另设redact防线，自由文本仍须由调用方避免写入秘密。运行日志不承担业务审计功能。

Git根目录是上级学习笔记，self-ecom起初只有项目文档。Node位于D:\develop\nodejs。Docker Desktop程序位于用户AppData，D:\Docker存放WSL数据。Docker29.8.2/Compose5.5.1；现已启动postgres:16.6-bookworm，通过15432映射到容器5432，避免本机现有PostgreSQL端口冲突。
