# 爬虫实战：axios 抓取网页、cheerio 解析与文件落地

> 学习日期：2026-11-05
> 素材来源：小满 NestJS 系列（blog.csdn.net/qq1195566313，专栏 ID 11844396）
> 本篇对应：原文第 20 章
> 适合人群：NestJS 零基础

前面 8 篇都在讲"服务端怎么接住别人发来的请求"。这一篇反过来：**我们的服务端主动去别人的网站取数据**。

这就是爬虫。原文开头说了句实话：**"爬虫是一个对计算机综合能力要求比较高的技术活"** —— 因为它卡的不是框架知识，而是对 HTTP 协议、页面结构、异步流程的综合理解。

别被"爬虫"这个词吓住。一个最简单的爬虫只干三件事：

```
发请求拿到 HTML → 从 HTML 里挑出想要的数据 → 存下来
```

这一篇就按这三步走，最后把它包成一个正经的 NestJS 接口。

## 一、爬虫到底是什么

### 1.1 先用大白话理解

你在浏览器里打开一个网页，背后发生的事是：

1. 浏览器向服务器发了一个 HTTP 请求；
2. 服务器返回一堆 HTML 文本；
3. 浏览器把这堆文本"翻译"成你看到的页面。

**爬虫就是用一个程序替代浏览器去做第 1 步，然后跳过第 3 步，直接用代码去第 2 步的 HTML 文本里翻找数据。**

区别只在于：

| 对比 | 人用浏览器 | 程序用爬虫 |
| --- | --- | --- |
| 发请求 | 地址栏敲回车 | `axios.get(url)` |
| 看内容 | 眼睛看渲染后的页面 | 看返回的 HTML 字符串 |
| 找数据 | 鼠标复制粘贴 | `cheerio` 按 CSS 选择器提取 |
| 存数据 | Ctrl+V 到文件 | `fs.createWriteStream()` 写盘 |
| 数量 | 手动几十个就累死 | 循环几千个不带喘 |

所以爬虫的核心能力不是"写代码"，而是**能不能看懂"数据藏在 HTML 的哪个位置"**。

### 1.2 爬虫的三个固定步骤

原文的章节划分其实就是这三步，非常标准：

| 步骤 | 做什么 | 用到的东西 |
| --- | --- | --- |
| 第一步 分析网页 | 在浏览器开发者工具里找到目标数据所在的 HTML 结构 | Chrome DevTools → Network / Elements 面板 |
| 第二步 抓取数据 | 发请求拿 HTML，按选择器提取，处理分页递归 | `axios` + `cheerio` |
| 第三步 落地存储 | 把抓到的内容写到本地文件或数据库 | `fs` / `fs.createWriteStream` |

**顺序不能颠倒。** 很多新手一上来就写代码，结果选择器写错了，抓回来一堆空数组，白忙半天。先看清楚结构，再动手。

### 1.3 两把必备工具

| 工具 | 是什么 | 在本篇的角色 | 安装 |
| --- | --- | --- | --- |
| `axios` | 基于 Promise 的 HTTP 请求库，能发 GET / POST，能设请求头，能拿二进制 | **取数据**：把网页 HTML 拉回来 | `npm i axios` |
| `cheerio` | jQuery 核心功能在服务端的实现，用熟悉的 `$` 语法操作 DOM | **找数据**：在 HTML 字符串里按选择器提取 | `npm i cheerio` |

原文对 cheerio 的描述很到位：**"是 jQuery 核心功能的一个快速灵活而又简洁的实现，主要是为了用在服务器端需要对 DOM 进行操作的地方，让你在服务器端和 html 愉快地玩耍。"**

一句话记住分工：**axios 负责"搬砖"，cheerio 负责"挑砖"。**

为什么不直接用正则表达式匹配 HTML？可以，但极其脆弱 —— 页面多一个空格、属性顺序变一下，正则就崩了。cheerio 按 DOM 结构匹配，稳定性高一个量级。

### 1.4 动手前先学会看 Network 面板

原文特意强调："简单的情况使用 chrome devtools 的 network 面板就够了"。

操作步骤：

1. 打开目标网页，按 `F12` 打开开发者工具；
2. 切到 **Network（网络）** 面板，勾选 `Fetch/XHR` 可以过滤掉图片、CSS 等干扰；
3. 按 `F5` 刷新页面，看列表里出现了哪些请求；
4. 点任意一条，右侧能看到 **Headers**（请求地址、请求头）、**Preview / Response**（返回内容）、**Payload**（发了什么参数）。

判断一件事：**你要的数据，是直接在 HTML 文档里，还是靠接口（XHR）异步加载的？**

| 情况 | 表现 | 抓取方式 |
| --- | --- | --- |
| 服务端渲染（SSR） | 右键"查看网页源代码"能看到数据 | 直接抓 HTML 首页，用 cheerio 解析 |
| 前端渲染（SPA） | 源代码里只有 `<div id="app"></div>` | 必须抓 XHR 接口，直接请求 JSON |

本篇的素材属于第一种：图片地址就写在 HTML 的 `<p><img src="...">` 里，所以直接抓页面 HTML 即可。

再切到 **Elements（元素）** 面板，用左上角的箭头工具点一下目标图片，就能看到它在 DOM 树里的位置和祖先标签的 class：

```
<div class="article-content">
  <p><img src="/upload/xxx/1.jpg"></p>
  <p><img src="/upload/xxx/2.jpg"></p>
  ...
  <div class="pagination">
    <a>上一页</a> <a>下一页</a>
  </div>
</div>
```

原文的结论就是这一句：**"发现图片是在 article-content 下面的 p 标签"**。据此写出选择器：

```js
$('.article-content p img') // 类名 article-content 内部的 p 里的 img
```

> 选择器中间的**空格表示后代关系**（任意层级），而不是直接子元素。如果要直接子元素用 `>`：`.article-content > p > img`。

## 二、准备环境

### 2.1 安装依赖

```bash
# 在 NestJS 项目根目录执行
npm i axios cheerio
```

如果用到 NestJS 官方的封装的 HTTP 模块（下面 2.2 讲），还要装：

```bash
npm i @nestjs/axios
```

### 2.2 直接用 axios，还是用 `HttpModule`？

NestJS 官方提供了 `@nestjs/axios` 包，里面导出 `HttpModule` 和 `HttpService`。这是新手最容易困惑的地方，先说清楚：

> **`HttpModule` 内部用的就是 axios**，它只是把 axios 包成了"可注入的 Service"，让你能享受 NestJS 的依赖注入和统一配置。

| 对比 | 直接 `import axios from 'axios'` | 用 `HttpModule` + `HttpService` |
| --- | --- | --- |
| 写法 | 随处 import，直接调用 | 构造函数注入 `HttpService` |
| 单元测试 | 要 mock 整个 axios 模块 | 可以 `provide` 一个假的 `HttpService` |
| 统一配置 | 每个调用点自己设 baseURL、超时 | 在模块里配一次，全局生效 |
| 拦截器 | 全局改 axios 默认值 | 支持 `axiosRef` + RxJS 管道 |
| 返回值 | `Promise` | `Observable`（配合 `firstValueFrom` 或 `lastValueFrom` 转回 Promise） |
| 适合 | 脚本、一次性任务、学习阶段 | 生产项目、需要测试与统一治理 |

**建议**：跟着原文先用直接 axios 把逻辑跑通（更好理解本质），跑通后再改造成 `HttpModule` 版本。

### 2.3 `HttpModule` 版本的写法

先在模块里注册：

```ts
// src/crawler/crawler.module.ts
import { Module } from '@nestjs/common';
import { HttpModule } from '@nestjs/axios';
import { CrawlerService } from './crawler.service';
import { CrawlerController } from './crawler.controller';

@Module({
  imports: [
    HttpModule.register({
      timeout: 10000, // 超时 10 秒，防止请求一直挂着
      maxRedirects: 5, // 最多跟随 5 次重定向
      headers: {
        // 伪装成浏览器，很多站点会直接拒绝默认的 axios UA
        'User-Agent':
          'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0 Safari/537.36',
      },
    }),
  ],
  controllers: [CrawlerController],
  providers: [CrawlerService],
})
export class CrawlerModule {}
```

在 Service 里注入使用：

```ts
import { Injectable } from '@nestjs/common';
import { HttpService } from '@nestjs/axios';
import { firstValueFrom } from 'rxjs'; // 把 Observable 转成 Promise 的小工具

@Injectable()
export class CrawlerService {
  constructor(private readonly httpService: HttpService) {}

  async getHtml(url: string): Promise<string> {
    // HttpService 返回的是 Observable，用 firstValueFrom 转成 Promise 才能 await
    const res = await firstValueFrom(this.httpService.get(url));
    return res.data;
  }
}
```

> `firstValueFrom` 会取流的第一个值后自动完成（等价于老版本的 `toPromise()`）。**只发一次请求的场景用它就够了**，用 `lastValueFrom` 也没问题，区别是后者会等流结束。

后面为了贴合原文、也为了让代码更直白，**主流程仍用直接 axios 演示**，最后 6 节再合并成一个完整的 `HttpModule` 版本。

## 三、第一步：拆解页面结构

### 3.1 找到图片藏在哪里

假设目标页面是一个图片列表页，结构简化后长这样：

```html
<div class="article-content">
  <p><img src="/upload/2022/cosplay/10772/1.jpg"></p>
  <p><img src="/upload/2022/cosplay/10772/2.jpg"></p>
  <p><img src="/upload/2022/cosplay/10772/3.jpg"></p>

  <!-- 分页区，下一页的链接文字就是"下一页" -->
  <div class="pagination">
    <a href="...">上一页</a>
    <a href="...">下一页</a>
  </div>
</div>
```

要抓的东西有两个：

| 目标 | 选择器 | 提取内容 |
| --- | --- | --- |
| 图片地址 | `.article-content p img` | `src` 属性 |
| 是否有下一页 | `.article-content .pagination a` | 标签文本是不是"下一页" |

### 3.2 先用几行代码验证选择器

**这是整篇最重要的一条经验**：写正式代码前，先花 30 秒验证选择器能不能选到东西。

```ts
// 临时验证脚本 verify.ts
import axios from 'axios';
import * as cheerio from 'cheerio';

async function main() {
  const res = await axios.get('https://example.com/cosplay/10772.html');
  const $ = cheerio.load(res.data); // 把 HTML 字符串装进 cheerio

  console.log('图片数量：', $('.article-content p img').length);
  console.log('第一张：', $('.article-content p img').first().attr('src'));
  console.log('分页文字：', $('.article-content .pagination a').map(function () {
    return $(this).text();
  }).toArray());
}

main();
```

输出类似：

```
图片数量： 8
第一张： /upload/2022/cosplay/10772/1.jpg
分页文字： [ '上一页', '下一页' ]
```

数量不是 0，说明选择器对了；如果是 0，说明：

- 类名拼错了（大小写、连字符）；
- 数据是 JS 异步加载的，HTML 里本来就没有（回到 1.4 节判断）。

### 3.3 拼接完整地址

`src` 拿到的是 `/upload/xxx.jpg` 这种**相对路径**，没有域名。想下载它，必须拼上站点的 baseUrl：

```ts
const baseUrl = 'https://example.com'; // 只到域名，不要带斜杠结尾
const src = '/upload/2022/cosplay/10772/1.jpg';

const fullUrl = baseUrl + src;
// https://example.com/upload/2022/cosplay/10772/1.jpg
```

> 判断要不要拼：`src` 以 `http` 开头就是绝对地址，直接用；以 `/` 开头是站内绝对路径，拼「域名」；以 `img/` 开头是相对当前页的路径，拼「当前页目录」。原文做的是最简单的第一种拼法。

## 四、第二步：递归抓取所有分页

### 4.1 先找分页的规律

原文发现的分页规律是：第一页 `Cosplay10772.html`，第二页 `Cosplay10772_2.html`，第三页 `Cosplay10772_3.html`……

所以第 N 页（N ≥ 2）的地址是：

```
域名/Cosplay/Cosplay10772_2.html
```

这种"URL 里带递增数字"的分页最好处理 —— 可以**直接拼 URL 循环**，也可以**像原文那样递归判断"有没有下一页"**。

两种策略对比：

| 策略 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 固定次数循环 | 先知道总页数，`for (let i = 1; i <= 10; i++)` | 简单、可控 | 总页数未知时要先数一遍 |
| 递归判断 | 抓当前页 → 看有没有"下一页" → 有就再抓 | 不用预先知道页数 | 递归深度需设上限，否则可能死循环 |

原文用的是**递归判断**，逻辑是：**只要页面上还有"下一页"，就往下抓。**

### 4.2 递归函数完整代码

素材原样（代码块部分保持一致，只补注释）：

```ts
const baseUrl = 'xxxxxxxxxxxxxxxxxxxxxxx'; // 站点域名
const next = '下一页'; // 用来判断是否还有下一页的标识文字
let index = 0; // 当前页码索引，第一页为 0
const urls: string[] = []; // 收集所有图片地址

const getCosPlay = async () => {
  console.log(index); // 打印当前页，方便观察进度

  // 拼接当前页地址：index 为 0 时是第一页（无后缀），否则是 _2、_3 ...
  await axios
    .get(`xxxxxxxxxxxxxx/Cosplay/Cosplay10772${index ? '_' + index : ''}.html`)
    .then(async (res) => {
      // 1. 把返回的 HTML 交给 cheerio
      const $ = cheerio.load(res.data);

      // 2. 取分页区所有 a 标签的文字，转成数组
      const page = $('.article-content .pagination a')
        .map(function () {
          return $(this).text();
        })
        .toArray();

      // 3. 如果文字里包含"下一页"，说明还有后续页面
      if (page.includes(next)) {
        // 3.1 先把当前页所有图片地址收进数组
        $('.article-content p img').each(function () {
          console.log($(this).attr('src'));
          urls.push(baseUrl + $(this).attr('src')); // 拼接完整地址
        });

        // 3.2 页码 +1，递归抓下一页
        index++;
        await getCosPlay();
      }
    });
};

await getCosPlay();
console.log(urls); // 所有图片地址都收齐了
```

### 4.3 逐段拆解

| 代码片段 | 在干什么 | 关键点 |
| --- | --- | --- |
| `index ? '_' + index : ''` | 三元表达式拼页码后缀 | `index` 为 0 时得到空串，正好是第一页的地址 |
| `cheerio.load(res.data)` | 把 HTML 字符串解析成可查询的 DOM | `res.data` 是 axios 自动解析好的文本 |
| `$('.article-content .pagination a')` | 选中分页区所有链接 | 中间空格 = 后代选择器 |
| `.map(function () { return $(this).text() })` | 遍历取每项的文本 | **必须用 `function`**，不能用箭头函数（见下方坑） |
| `.toArray()` | 把 cheerio 集合转成普通数组 | 转完才能用 `includes`、`forEach` |
| `page.includes(next)` | 判断有没有"下一页" | 靠页面文案判断，做法简单但脆弱 |
| `$('.article-content p img').each(function () {...})` | 遍历每张图片 | 同上，`this` 才是当前 DOM |
| `$(this).attr('src')` | 取图片源地址 | 返回相对路径，需拼域名 |
| `await getCosPlay()` | 递归调用自己 | 必须 `await`，否则外层先结束、数据没收完 |
| `await getCosPlay()` 最后一行 | 启动递归 | 顶层 await（Node 14+ ESM 支持） |

### 4.4 为什么 `map` 里必须用 `function`

这是 cheerio 最容易踩的坑之一：

```ts
// ❌ 错误：箭头函数里的 this 指向模块作用域，不是当前 DOM 元素
$('.pagination a').map(() => $(this).text()); // this 是 undefined

// ✅ 正确：function 里的 this 才由 cheerio 绑定为当前元素
$('.pagination a').map(function () {
  return $(this).text();
});
```

原因是箭头函数**没有自己的 `this`**，而 cheerio（和 jQuery 一样）在遍历时会把 `this` 绑定成当前元素。想用箭头函数的话，改用回调参数：

```ts
// ✅ 也可以用参数，cheerio 第二个参数就是当前元素
$('.pagination a').map((i, el) => $(el).text());
```

### 4.5 递归的隐患：必须设上限

原文这段递归逻辑能跑通，但**用于生产必须加保护**，否则可能出现：

- 网站分页链接是"下一页"循环指回自己 → **无限递归**；
- 最后一页也带着"下一页"文字（只是不可点）→ 一直抓同一个页面；
- 请求失败时会静默退出（`.then` 里抛错没人 catch）。

修正版：

```ts
async function crawlAll(startUrl: string, maxPage = 20): Promise<string[]> {
  const urls: string[] = [];
  // 从起始地址里取出域名，用于把相对路径拼成完整地址
  const origin = new URL(startUrl).origin;
  let index = 0;

  // 用 while 循环代替递归，天然避免栈溢出，也更好控制退出
  while (index < maxPage) {
    // 第一页用原始地址，后续页拼 _2、_3 后缀
    const pageUrl =
      index === 0
        ? startUrl
        : `${startUrl.replace(/\.html$/, '')}_${index + 1}.html`;
    console.log(`正在抓第 ${index + 1} 页 → ${pageUrl}`);

    let $: cheerio.CheerioAPI;
    try {
      const res = await axios.get(pageUrl, {
        timeout: 10000, // 单页超时，避免卡死
        headers: { 'User-Agent': 'Mozilla/5.0 ...' }, // 伪装浏览器
      });
      $ = cheerio.load(res.data);
    } catch (err) {
      console.error(`第 ${index + 1} 页抓取失败，终止：`, err.message);
      break; // 抓不到就停，不要把异常吞掉继续跑
    }

    // 收当前页图片
    $('.article-content p img').each(function () {
      const src = $(this).attr('src');
      // 绝对地址直接用，相对路径拼上域名
      if (src) urls.push(src.startsWith('http') ? src : origin + src);
    });

    // 判断还有没有下一页
    const pageTexts = $('.article-content .pagination a')
      .map(function () {
        return $(this).text().trim();
      })
      .toArray();

    if (!pageTexts.includes('下一页')) break; // 没有下一页就收工

    index++;
  }

  return urls;
}
```

三条改进：

| 问题 | 原写法 | 修正 |
| --- | --- | --- |
| 无限递归 | 只靠页面文字判断 | 加 `maxPage` 硬上限 |
| 错误被吞 | `.then()` 里没 catch | `try/catch` 明确终止并记录 |
| 栈深度 | 递归 20 层没问题，1000 层可能爆栈 | 改 `while` 循环，无栈增长 |

## 五、第三步：把图片写到硬盘

### 5.1 为什么用 `responseType: 'arraybuffer'`

抓图片和抓 HTML 有个本质区别：

- HTML 是**文本**，axios 默认按字符串返回，可以 `cheerio.load(res.data)`；
- 图片是**二进制**，如果也按字符串处理，内容会被转码破坏，存下来就是坏图（打不开）。

所以下载图片时必须显式指定 `responseType: 'arraybuffer'`：

```ts
const res = await axios.get(imgUrl, {
  responseType: 'arraybuffer', // 关键：让 axios 返回原始二进制 Buffer
});
const buffer = res.data; // 此时 data 是 Buffer，可以原样写文件
```

| 场景 | `responseType` | `res.data` 类型 |
| --- | --- | --- |
| 抓 HTML 页面 | 默认 `'text'` | `string` |
| 抓 JSON 接口 | 默认（axios 自动识别） | `object` |
| 下载图片 / 视频 / PDF | `'arraybuffer'` | `Buffer` |
| 需要进度条的大文件 | `'stream'` | `Readable` 流 |

### 5.2 素材的写盘代码

```ts
writeFile(urls: string[]) {
  urls.forEach(async (url) => {
    // 1. 以二进制方式下载
    const buffer = await axios
      .get(url, { responseType: 'arraybuffer' })
      .then((res) => res.data);

    // 2. 创建可写流，路径用时间戳当文件名
    const ws = fs.createWriteStream(
      path.join(__dirname, '../cos' + new Date().getTime() + '.jpg'),
    );

    // 3. 写入
    ws.write(buffer);
  });
}
```

这段代码能工作，但**有三个必须知道的坑**：

| 坑 | 表现 | 原因 |
| --- | --- | --- |
| `forEach` + `async` 不受控 | 函数已经返回了，图片还在慢慢下；报错也没人管 | `forEach` 不会等待 `async` 回调完成 |
| `new Date().getTime()` 重名 | 同一毫秒下载两张图，第二张把第一张**覆盖**了 | 时间戳精度只到毫秒 |
| 目录不存在直接崩 | `ENOENT: no such file or directory` | `createWriteStream` 不会自动创建父目录 |
| 没调用 `ws.end()` | 文件写一半、内容截断 | 流没有正常关闭 |

### 5.3 `__dirname` 指向 `dist` 的坑（和 05 篇同一个雷）

`__dirname` 在 NestJS 编译后指向的是 `dist` 目录，不是 `src`！

```
开发时：D:\project\src\crawler\crawler.service.ts
运行时：D:\project\dist\crawler\crawler.service.js   ← __dirname 在这里
```

所以 `path.join(__dirname, '../cos.jpg')` 实际会落到 `dist/../cos.jpg`（即项目根目录）。这不是错，但**如果你以为它写到 `src` 下，就会找不到文件**。

推荐显式指向项目根目录下的 `downloads`：

```ts
import * as path from 'path';
import * as fs from 'fs';

// process.cwd() 是执行 node 命令的目录，在 NestJS 里就是项目根目录
const DOWNLOAD_DIR = path.join(process.cwd(), 'downloads');

// 第一次用之前确保目录存在（写成函数，每次调用都检查，成本极低）
function ensureDir() {
  if (!fs.existsSync(DOWNLOAD_DIR)) {
    fs.mkdirSync(DOWNLOAD_DIR, { recursive: true });
  }
}
```

### 5.4 改良版：用 `pipeline` 流式下载

比"buffer 全读进内存再写"更稳的做法是**直接把响应流管到文件流**：

```ts
import axios from 'axios';
import * as fs from 'fs';
import * as path from 'path';
import { pipeline } from 'stream/promises'; // Node 15+ 提供 Promise 版

async function downloadImage(url: string, filename: string) {
  ensureDir(); // 保证目录存在

  const filePath = path.join(DOWNLOAD_DIR, filename);

  // 1. 以流的方式请求（不会把整张图先吃进内存）
  const response = await axios.get(url, {
    responseType: 'stream',
    timeout: 30000,
    headers: { 'User-Agent': 'Mozilla/5.0 ...' },
  });

  // 2. 管道接到写入流；pipeline 会自动处理错误、自动关闭两端
  await pipeline(response.data, fs.createWriteStream(filePath));

  return filePath;
}
```

批量下载时，**串行**比并发更安全（对目标站点也更礼貌）：

```ts
async function downloadAll(urls: string[]) {
  const results: string[] = [];

  // 用 for...of 而不是 forEach：这样 await 才真的生效
  for (const [i, url] of urls.entries()) {
    try {
      // 从 URL 里取扩展名，取不到就默认 jpg
      const ext = path.extname(new URL(url).pathname) || '.jpg';
      // 序号 + 时间戳，绝不会重名
      const filename = `${String(i + 1).padStart(3, '0')}_${Date.now()}${ext}`;

      const saved = await downloadImage(url, filename);
      console.log(`✅ 第 ${i + 1}/${urls.length} 张完成：${filename}`);
      results.push(saved);
    } catch (err) {
      // 单张失败不影响整体，记录后继续
      console.error(`❌ 第 ${i + 1} 张失败：${url}`, err.message);
    }
  }

  return results;
}
```

对比一下两版写盘：

| 维度 | 素材版 | 改良版 |
| --- | --- | --- |
| 等待 | `forEach` + `async`，主流程不等 | `for...of` + `await`，严格串行 |
| 内存 | 整张图进内存 Buffer | 流式，边下边写 |
| 关闭流 | 没调 `end()`，可能截断 | `pipeline` 自动关闭 |
| 重名 | 毫秒时间戳，可能覆盖 | 序号 + 时间戳 |
| 目录 | 不存在直接报错 | `mkdirSync(recursive)` |
| 单张失败 | 整个链路静默中断 | `try/catch` 记录后继续 |

### 6.2 `crawler.service.ts`

```ts
import { Injectable, Logger } from '@nestjs/common';
import axios from 'axios';
import * as cheerio from 'cheerio';
import * as fs from 'fs';
import * as path from 'path';

@Injectable()
export class CrawlerService {
  // NestJS 内置日志器，比 console.log 更适合服务端
  private readonly logger = new Logger(CrawlerService.name);

  // 下载目录：项目根目录下的 downloads
  private readonly downloadDir = path.join(process.cwd(), 'downloads');

  /**
   * 抓取指定页面的所有图片地址
   * @param startUrl 第一页地址
   * @param maxPage  最多抓多少页（防御手段，必须设）
   */
  async crawlImages(startUrl: string, maxPage = 5): Promise<string[]> {
    const urls: string[] = [];
    // 用 URL 对象安全地取出域名，避免手写字符串截取
    const origin = new URL(startUrl).origin;
    let index = 0;

    while (index < maxPage) {
      // 第一页用原始地址，后续拼 _2、_3
      const pageUrl =
        index === 0
          ? startUrl
          : `${startUrl.replace(/\.html$/, '')}_${index + 1}.html`;

      this.logger.log(`开始抓取第 ${index + 1} 页：${pageUrl}`);

      try {
        const res = await axios.get(pageUrl, {
          timeout: 10000,
          headers: {
            'User-Agent':
              'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120.0 Safari/537.36',
          },
        });

        const $ = cheerio.load(res.data);

        // 收集本页图片
        $('.article-content p img').each(function () {
          const src = $(this).attr('src');
          if (!src) return;
          // 绝对地址直接存，相对地址拼上域名
          urls.push(src.startsWith('http') ? src : origin + src);
        });

        // 看还有没有下一页
        const pageTexts = $('.article-content .pagination a')
          .map(function () {
            return $(this).text().trim();
          })
          .toArray();

        if (!pageTexts.includes('下一页')) {
          this.logger.log('没有下一页，抓取结束');
          break;
        }
      } catch (err) {
        // 单页失败：记录并终止，不抛出 500（前端还能拿到已抓到的部分）
        this.logger.error(`第 ${index + 1} 页抓取失败：${err.message}`);
        break;
      }

      index++;
    }

    // 去重，防止分页重叠导致重复下载同一张图
    const unique = [...new Set(urls)];
    this.logger.log(`共抓取到 ${unique.length} 张图片地址`);
    return unique;
  }

  /**
   * 把图片下载到本地
   * @param urls 图片地址列表
   */
  async downloadImages(urls: string[]): Promise<string[]> {
    // 确保目录存在，否则写入流会抛 ENOENT
    if (!fs.existsSync(this.downloadDir)) {
      fs.mkdirSync(this.downloadDir, { recursive: true });
    }

    const saved: string[] = [];

    for (const [i, url] of urls.entries()) {
      try {
        const res = await axios.get(url, {
          responseType: 'arraybuffer', // 二进制必须指定
          timeout: 30000,
        });

        const ext = path.extname(new URL(url).pathname) || '.jpg';
        const filename = `${String(i + 1).padStart(3, '0')}_${Date.now()}${ext}`;
        const filePath = path.join(this.downloadDir, filename);

        // 写文件：写入后必须 close / 用同步写法最稳
        fs.writeFileSync(filePath, Buffer.from(res.data));

        saved.push(filePath);
        this.logger.log(`已保存 ${i + 1}/${urls.length}：${filename}`);
      } catch (err) {
        this.logger.error(`下载失败：${url} → ${err.message}`);
      }
    }

    return saved;
  }
}
```

### 6.3 `crawler.controller.ts`

```ts
import { Controller, Get, Query, Post, Body, ForbiddenException } from '@nestjs/common';
import { ApiOperation, ApiQuery, ApiTags } from '@nestjs/swagger';
import { CrawlerService } from './crawler.service';

@ApiTags('爬虫演示')
@Controller('crawler')
export class CrawlerController {
  constructor(private readonly crawlerService: CrawlerService) {}

  @Get('images')
  @ApiOperation({ summary: '抓取目标页图片地址（只抓不下载）' })
  @ApiQuery({ name: 'url', description: '起始页地址', required: true })
  @ApiQuery({ name: 'maxPage', description: '最多抓几页，默认 3', required: false })
  async getImages(@Query('url') url: string, @Query('maxPage') maxPage = '3') {
    // 只允许 http/https，防止被传入 file:// 之类的协议
    if (!/^https?:\/\//i.test(url ?? '')) {
      throw new ForbiddenException('url 必须是 http 或 https 地址');
    }

    const urls = await this.crawlerService.crawlImages(url, Number(maxPage));
    return {
      total: urls.length,
      urls, // 直接把爬取结果返回给前端
    };
  }

  @Post('download')
  @ApiOperation({ summary: '把图片批量下载到服务器 downloads 目录' })
  async download(@Body('urls') urls: string[]) {
    if (!Array.isArray(urls) || urls.length === 0) {
      throw new ForbiddenException('urls 不能为空');
    }
    const files = await this.crawlerService.downloadImages(urls);
    return { saved: files.length, files };
  }
}
```

## 七、反爬手段与合规注意事项

原文只提了一句"要对 HTTP 协议有基本了解"，但真实项目里这一节比代码更关键。

### 7.1 常见反爬手段

| 手段 | 表现 | 说明 |
| --- | --- | --- |
| 校验 `User-Agent` | 返回 403，或返回一个假页面 | 最简单的门槛，请求头里没有浏览器 UA 就拒 |
| 校验 `Referer` | 图片 403、返回防盗链占位图 | 只允许从自己域名跳转过来的请求 |
| 频率限制（限流） | 快速请求后返回 429 或直接封 IP | 按 IP / 账号 / 时间窗统计 |
| IP 封禁 | 一段时间内所有请求超时 | 换 IP 或加代理池 |
| JS 动态渲染 | HTML 里没有数据，只有 `<div id="app">` | 数据由前端 JS 请求 XHR 后渲染 |
| 登录 / Cookie 校验 | 未登录跳转登录页 | 需要带着有效 Cookie 或 token |
| 签名 / 加密参数 | URL 里有 `sign`、`t`、`token` 参数 | 参数由前端 JS 计算，难度最高 |
| 验证码 | 弹出滑块 / 图形验证码 | **不要尝试绕过**，直接停 |
| 动态 class 名 | class 是 `a3f2x` 这种随机串 | 选择器每次都得重新找 |

### 7.2 应对方式

| 手段 | 应对思路 | 备注 |
| --- | --- | --- |
| UA 校验 | 请求头里带真实浏览器的 UA | 最基础，几乎必做 |
| Referer 校验 | 加上 `Referer: 站点域名` | 抓图片时常用 |
| 频率限制 | `await sleep(1000)` 每张间隔 1 秒 | 见下方 `sleep` 写法 |
| JS 渲染 | 换用 Puppeteer / Playwright 驱动真实浏览器 | 成本高，能不用就不用 |
| 数据在 XHR | 直接抓接口的 JSON，比解析 HTML 稳得多 | **优先选择这条路** |
| 加密参数 | 分析前端 JS 逻辑复现 | 难度高，且容易触及法律边界 |

限速的简单实现：

```ts
// 睡一会儿再继续，降低对目标站点的压力
const sleep = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms));

for (const url of urls) {
  await downloadImage(url);
  await sleep(1000); // 每张图间隔 1 秒，避免被判为恶意爬取
}
```

### 7.3 必须守住的三条红线

| 红线 | 说明 |
| --- | --- |
| 不抓隐私与个人信息 | 手机号、身份证、住址、医疗记录等，抓取即违法（《个人信息保护法》） |
| 不绕过技术保护措施 | 破解登录、绕过付费墙、破解验证码、伪造签名参数，都可能触犯法律 |
| 遵守 `robots.txt` 与站点协议 | 访问 `https://站点/robots.txt` 看 `Disallow` 规则；遵守服务条款与版权 |

再加两条工程纪律：

- **控速**：请求间隔 ≥ 1 秒，别把别人的服务器打挂（这可能构成破坏计算机信息系统）。
- **只用来自用的数据**：抓下来的图片/文章有版权，**不能二次分发或商用**。本篇所有示例仅用于技术学习。

## 八、常见错误提示

| 报错原文 | 原因 | 解决 |
| --- | --- | --- |
| `TypeError: cheerio.load is not a function` | 用了 `import cheerio from 'cheerio'`（Named export 变了） | 改 `import * as cheerio from 'cheerio'` |
| 选择器结果 `length: 0` | 类名写错；或数据是 JS 渲染的 | `console.log(res.data)` 看原始 HTML；改用抓 XHR 接口 |
| `this.text is not a function` | `map` 里用了箭头函数，`this` 不是 DOM | 改 `function () {}` 或用 `(i, el) => $(el)` |
| `fs.createWriteStream` 保存的图片打不开 | 下载时没设 `responseType: 'arraybuffer'` | 补 `responseType: 'arraybuffer'`，并用 `Buffer.from(data)` |
| `ENOENT: no such file or directory` | 目标目录不存在 | `fs.mkdirSync(dir, { recursive: true })` 先建目录 |
| `RangeError: Maximum call stack size exceeded` | 递归没有终止条件 | 用 `while` + `maxPage` 上限 |
| 所有图片文件名一样、只剩一张 | 用毫秒时间戳命名，并发时重名覆盖 | 文件名加序号或随机串 |
| `409 Conflict` / 403 / 返回假页面 | 被反爬拦了（UA 或 Referer 校验） | 请求头补 `User-Agent`、`Referer` |
| `429 Too Many Requests` | 请求太快触发限流 | 加间隔 `sleep(1000)` |
| `axios.get(...).then is not a function` | 混用了 `Observable` 与 `Promise` | `HttpService` 返回 `Observable`，要 `firstValueFrom()` |
| `Cannot find name 'require'` / ESM 报错 | TS 环境用 CommonJS `require` 或顶层 `await` | 用 `import`；顶层 await 需 `"type": "module"` |
| 下载的文件全是几 KB 的占位图 | 命中防盗链，返回的是"禁止外链"图片 | 补 `Referer` 头 |

## 九、本篇小结

| 要点 | 一句话说明 |
| --- | --- |
| 爬虫的本质 | 用程序代替浏览器发请求，直接从 HTML 里取数据 |
| 固定三步 | 分析页面结构 → 抓取解析 → 落地存储，顺序不能颠倒 |
| 分工 | `axios` 负责取（发请求），`cheerio` 负责挑（解析 DOM） |
| 动手前必做 | 打开 DevTools 的 Network / Elements，先确认数据藏在哪个标签 |
| 判断页面类型 | 源码里有数据 = SSR 直接抓；只有 `<div id="app">` = 抓 XHR 接口 |
| 选择器语法 | `.article-content p img`，中间**空格**表示任意层级后代 |
| 类名 | jQuery 核心在服务端的实现，API 就是 `$` |
| `cheerio.load` | 把 HTML 字符串装进 cheerio 才能查询 |
| `map` 的 this | 必须用 `function`，箭头函数没有自己的 `this` |
| `toArray()` | 转成普通数组后才能用 `includes` / `forEach` |
| 相对路径拼域名 | `src` 以 `/` 开头时要拼 `baseUrl` 才能下载 |
| 递归分页 | 靠"下一页"文字判断，但**必须**设最大页数上限 |
| 递归改循环 | `while` 不会栈溢出，也更好控制退出条件 |
| 错误不能吞 | `.then` 里失败没人 catch，要写 `try/catch` 明确终止 |
| 下载二进制 | 必须 `responseType: 'arraybuffer'`，否则图片全坏 |
| 大文件更优解 | `responseType: 'stream'` + `pipeline`，边下边写不吃内存 |
| 写文件必关流 | `writeFileSync` 最稳，或 `pipeline` 自动关闭 |
| `forEach` + `async` 陷阱 | 主流程不会等待，批量下载必须用 `for...of` + `await` |
| 文件名不能只用时间戳 | 毫秒级并发会重名覆盖，要加序号或随机串 |
| 目录要先创建 | `mkdirSync(dir, { recursive: true })`，否则 `ENOENT` |
| `__dirname` 指向 dist | 编译后路径变了，用 `process.cwd()` 定位项目根目录 |
| NestJS 封装 | Controller 只做参数校验与返回，抓取逻辑放 Service |
| 直接用 axios vs `HttpModule` | 前者直白适合学习，后者可注入、好测试，适合生产 |
| `HttpService` 返回 Observable | 要用 `firstValueFrom()` 转 Promise 才能 `await` |
| 长任务别放请求里 | 大批量抓取放队列/定时任务，接口只返回任务 ID |
| 爬虫接口必须鉴权 | 否则等于给外部一个替你发请求的工具（SSRF 风险） |
| 反爬常见手段 | UA、Referer、限流、IP 封禁、JS 渲染、签名、验证码 |
| 应对优先顺序 | 先补请求头 → 再加限速 → 最后才考虑无头浏览器 |
| 限速 | 每请求间隔 ≥ 1 秒，既是礼貌也是自我保护 |
| 三条红线 | 不抓隐私数据、不绕技术保护、遵守 `robots.txt` 与版权 |
*（内容由AI生成，仅供参考）*
