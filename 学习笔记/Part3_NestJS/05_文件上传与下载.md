# 文件上传与下载：Multer 上传、静态目录与流式下载

> 学习日期：2026-11-05
> 素材来源：小满 NestJS 系列（blog.csdn.net/qq1195566313，专栏 ID 11844396）
> 本篇对应：原文第 13、14 章
> 适合人群：NestJS 零基础

到这一篇，接口已经能收参数、能拦请求了。但还有一类数据没地方落：**文件**——用户头像、商品图、要导出的报表。

文件处理和普通 JSON 有本质不同：JSON 会被框架自动解析成对象，而文件是**二进制流**，需要一个专门的解析器把请求体拆开、把流写进磁盘。NestJS 选的解析器是 **Multer**。

本篇按真实开发顺序走一遍：**接收上传 → 存到磁盘 → 用 URL 访问 → 下载给用户**。

---

## 一、先说清原理：文件是怎么传上来的

### 1.1 先用大白话理解

还是用快递打比方：

- 你寄快递，不能把东西直接扔给快递员，得**装进标准纸箱、贴上运单**。运单上写着收件人、物品名称、数量。
- 网络世界里，上传文件时的"标准纸箱 + 运单"就是 **`multipart/form-data`** 这种请求格式。
- 但这个箱子运到服务器门口，**NestJS 自己不会拆箱**——它需要一个专门的拆箱工，就是 **Multer**。Multer 负责：把箱子拆开（解析请求体）→ 把里面的东西按运单上的名字（字段名）分好 → 交给你。

所以上传这件事的核心，不是"怎么传"，而是**配置好拆箱工把东西放到哪、叫什么名字**。

### 1.2 专业定义

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 多部分表单数据 | `multipart/form-data` | 上传文件专用的请求体格式，可同时携带文本字段和二进制文件 |
| 文件解析中间件 | Multer | Node.js 生态最流行的上传处理库，负责解析 `multipart/form-data` 并把文件写入磁盘或内存 |
| 上传模块 | `MulterModule` | NestJS 对 Multer 的封装模块，用 `register()` 做全局存储配置 |
| 磁盘存储引擎 | `diskStorage` | Multer 的存储引擎之一，把文件写到硬盘（另一类是 `memoryStorage` 存内存） |

### 1.3 依赖包：三个里只需装两个

| 包 | 作用 | 需要安装吗 |
| --- | --- | --- |
| `multer` | 核心解析库 | **要装** |
| `@types/multer` | TypeScript 类型声明（`Express.Multer.File` 就是它提供的） | **要装**（开发依赖） |
| `@nestjs/platform-express` | NestJS 对 Multer 的封装，**项目创建时就自带了** | 不用装 |

```bash
# 安装核心库
npm i multer

# 安装类型声明，提供 Express.Multer.File 类型提示
npm i @types/multer -D
```

> 小白提醒：`@nestjs/platform-express` 是默认平台包，`nest new` 时就装好了，`FileInterceptor`、`MulterModule` 都从它里面导出。**不要从 `multer` 包里去 import 这些 NestJS 的东西**，那是两个不同的包。

### 1.4 一次上传的完整链路

```
① 前端把文件塞进 FormData
   const fd = new FormData(); fd.append('file', 文件);
   注意 key 叫 'file' —— 这个名字后面要跟 FileInterceptor('file') 对上
        ↓
② 浏览器发出 POST /upload/album
   Content-Type: multipart/form-data; boundary=----xxx
        ↓
③ NestJS 收到请求，发现这个路由挂了 FileInterceptor('file')
   → 把请求体交给 Multer 解析
        ↓
④ Multer 按 MulterModule 里的配置干活：
   · diskStorage.destination 决定写到哪个目录
   · diskStorage.filename 决定新文件名
   → 文件落盘，得到一个 file 对象
        ↓
⑤ file 对象被挂到 req.file 上
   → @UploadedFile() 装饰器把它取出来给方法参数
        ↓
⑥ 你的 Controller 拿到 file.filename、file.size 等信息
   → 通常返回一个可访问的 URL 存进数据库
```

## 二、后端接收上传

### 2.1 第一步：在模块里注册存储目录

上传配置写在**模块**里，不在 Controller 里。用 `MulterModule.register()` 声明"文件存哪、叫什么"。

```ts
// src/upload/upload.module.ts
import { Module } from '@nestjs/common';
import { MulterModule } from '@nestjs/platform-express';
import { diskStorage } from 'multer';
import { extname, join } from 'path';
import { UploadService } from './upload.service';
import { UploadController } from './upload.controller';

@Module({
  imports: [
    MulterModule.register({
      // 使用磁盘存储引擎
      storage: diskStorage({
        // 文件存到哪个目录（注意：这个目录必须已存在）
        destination: join(__dirname, '../images'),

        // 文件存成什么名字
        filename: (req, file, callback) => {
          // 时间戳 + 原文件后缀，例：1662894316133.png
          const fileName = `${new Date().getTime()}${extname(file.originalname)}`;
          // 第一个参数是错误对象，没错误传 null；第二个是最终文件名
          callback(null, fileName);
        },
      }),
    }),
  ],
  controllers: [UploadController],
  providers: [UploadService],
})
export class UploadModule {}
```

### 2.2 这段配置逐行拆解

#### `diskStorage` 的两个必填回调

| 配置项 | 类型 | 作用 |
| --- | --- | --- |
| `destination` | 字符串 或 `(req, file, callback) => void` | 文件写到哪个目录 |
| `filename` | `(req, file, callback) => void` | 文件最终叫什么名字 |

两个都可以写成函数，这里 `destination` 用了字符串（固定目录），`filename` 用了函数（要动态生成）。

#### `filename` 回调的三个参数

```ts
filename: (req, file, callback) => {
  // req  ：当前请求对象，可以从中读用户信息、路由参数
  // file ：当前正在处理的文件信息
  // callback ：必须调用，把结果交回给 Multer
  callback(null, fileName);
}
```

`file` 对象在**写入磁盘之前**就已经有这些信息了：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `fieldname` | 前端 FormData 里的字段名 | `'file'` |
| `originalname` | 用户电脑上的原始文件名 | `'猫咪照片.png'` |
| `encoding` | 编码方式 | `'7bit'` |
| `mimetype` | MIME 类型 | `'image/png'` |
| `size` | 字节大小（部分场景下才有） | `204800` |

注意这里**还没有** `filename`、`path` 这些字段，因为文件还没落盘，名字是你现在决定的。

#### `extname()` 是什么

`extname` 来自 Node 内置的 `path` 模块，作用是**取出文件后缀（带点）**：

```ts
extname('猫咪照片.png'); // '.png'
extname('报表.tar.gz'); // '.gz'  只取最后一段
extname('没有后缀');     // ''
```

#### 关于原文的一个写法

原文写的是：

```ts
const fileName = `${new Date().getTime() + extname(file.originalname)}`;
```

`number + string` 在 JS 里会走字符串拼接，所以结果确实是 `"1662894316133.png"`，**能跑通**。但这是个"碰巧对"的写法：`+` 在这里既像加法又像拼接，读代码的人容易误解。本篇改成更直白的写法：

```ts
const fileName = `${new Date().getTime()}${extname(file.originalname)}`;
```

两者结果完全一致，只是后者意图更明确。也可以直接用 `Date.now()`，等价于 `new Date().getTime()`。

### 2.3 为什么要重命名（不能叫原名吗）

| 命名策略 | 写法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 原文件名 | `file.originalname` | 用户下载时看得懂 | **极大风险**：同名文件互相覆盖、中文名可能乱码、`../../etc/passwd` 这类恶意文件名可穿越目录 |
| 时间戳 | `${Date.now()}${extname(...)}` | 简单、基本不重复 | 同一毫秒多文件会撞名；名字没有可读性 |
| 时间戳 + 随机数 | `${Date.now()}-${Math.random().toString(36).slice(2)}${ext}` | 冲突概率极低 | 稍长 |
| UUID | `uuid()` | 全局唯一，最稳 | 需要装 `uuid` 包 |
| 内容哈希 | `md5(文件内容)` | 天然去重（同图只存一份） | 需要读完整文件，开销大 |

**结论：生产环境绝不要直接用 `originalname` 当存储文件名**，它来自用户，是不可信输入。本篇用时间戳方案，足够应对练习和中小项目。

### 2.4 第二步：Controller 里取文件

用 `FileInterceptor` 拦截并解析，再用 `@UploadedFile()` 把文件对象取出来。

```ts
// src/upload/upload.controller.ts
import {
  Controller,
  Post,
  UseInterceptors,
  UploadedFile,
} from '@nestjs/common';
import { FileInterceptor } from '@nestjs/platform-express';
import { UploadService } from './upload.service';

@Controller('upload')
export class UploadController {
  constructor(private readonly uploadService: UploadService) {}

  @Post('album')
  // 'file' 必须与前端 FormData 里的字段名完全一致
  @UseInterceptors(FileInterceptor('file'))
  upload(@UploadedFile() file: Express.Multer.File) {
    console.log(file);

    // 落盘后文件已经有 filename 了，可以拼出访问地址
    return {
      // /xiaoman 是 3.x 节里配置的静态目录虚拟前缀
      url: `/xiaoman/${file.filename}`,
      size: file.size,
      mimetype: file.mimetype,
    };
  }
}
```

**`FileInterceptor('file')` 里那个字符串是全篇最容易出错的地方**：

| 前端 FormData 的 key | 拦截器参数 | 结果 |
| --- | --- | --- |
| `'file'` | `FileInterceptor('file')` | 正常，`file` 有值 |
| `'avatar'` | `FileInterceptor('file')` | **`file` 是 `undefined`**，因为 Multer 只认 `file` 这个字段 |
| `'file'` | `FileInterceptor('avatar')` | 同样 `undefined` |

记住：**两边名字必须一模一样**。

### 2.5 多文件上传

单文件用 `FileInterceptor` + `@UploadedFile()`；多文件用 `FilesInterceptor` + `@UploadedFiles()`。

```ts
import {
  Controller,
  Post,
  UseInterceptors,
  UploadedFile,
  UploadedFiles,
} from '@nestjs/common';
import { FileInterceptor, FilesInterceptor } from '@nestjs/platform-express';

@Controller('upload')
export class UploadController {
  @Post('album')
  @UseInterceptors(FileInterceptor('file')) // 单文件
  upload(@UploadedFile() file: Express.Multer.File) {
    return { url: `/xiaoman/${file.filename}` };
  }

  @Post('albums')
  // 第二个参数是最大文件数量，超出会报错
  @UseInterceptors(FilesInterceptor('files', 10))
  uploadMany(@UploadedFiles() files: Express.Multer.File[]) {
    // files 是数组，逐个取文件名
    return files.map((f) => ({ url: `/xiaoman/${f.filename}` }));
  }
}
```

| 装饰器 | 配套取值装饰器 | 拿到什么 |
| --- | --- | --- |
| `FileInterceptor('字段名')` | `@UploadedFile()` | 单个 file 对象 |
| `FilesInterceptor('字段名', 最大数量)` | `@UploadedFiles()` | file 对象数组 |

### 2.6 前端怎么传（用 Apifox 快速验证）

后端写完了，先别急着写前端，用接口工具验证最快。在 Apifox / Postman 里：

1. 方法选 `POST`，URL 填 `http://localhost:3000/upload/album`。
2. `Body` 类型选 **`form-data`**（千万别选 JSON，文件传不上去）。
3. 添加一行：key 写 `file`，类型从 `Text` 切成 **`File`**，然后选择本地图片。
4. 发送。

返回 `{ "url": "/xiaoman/1662894316133.png" }` 就说明文件已经落盘了。

如果要在页面里写：

```ts
// 前端上传（原生 fetch 版）
const upload = async (file: File) => {
  const fd = new FormData();
  fd.append('file', file); // key 必须是 'file'

  const res = await fetch('http://localhost:3000/upload/album', {
    method: 'POST',
    body: fd, // 注意：不要手动设置 Content-Type！
  }).then((r) => r.json());

  console.log(res.url);
};
```

> **别手写 `Content-Type`**：`multipart/form-data` 的请求头里必须带一个 `boundary` 分隔符，浏览器会自动生成。你一旦手写 `'Content-Type': 'multipart/form-data'`，boundary 就丢了，后端解析直接失败。

### 2.7 补充：限制文件类型和大小

素材里没提，但这是同一个装饰器的第二个参数，顺手记一下（很实用）：

```ts
@Post('album')
@UseInterceptors(
  FileInterceptor('file', {
    // 限制大小：5MB
    limits: { fileSize: 5 * 1024 * 1024 },
    // 过滤类型：只允许图片
    fileFilter: (req, file, callback) => {
      if (!file.mimetype.startsWith('image/')) {
        // 第一个参数传错误，请求会被拒绝
        return callback(new Error('只允许上传图片'), false);
      }
      callback(null, true);
    },
  }),
)
upload(@UploadedFile() file: Express.Multer.File) {
  return { url: `/xiaoman/${file.filename}` };
}
```

> 注意：`fileFilter` 拒绝时抛的是普通 Error，默认会返回 500。正式项目里通常配合异常过滤器统一转成 400（后续章节的内容）。

### 2.8 常见错误与排查

**报错 1：`Error: ENOENT: no such file or directory, open 'D:\...\dist\images\1662894316133.png'`**

- 原因：`destination` 指向的目录**不存在**。Multer 只负责写文件，**不会帮你创建目录**。
- 解决：手动创建 `dist/images`（或你配置的那个目录），或在 `main.ts` 启动时用 `fs.mkdirSync(dir, { recursive: true })` 自动创建。

**现象 2：`@UploadedFile() file` 拿到 `undefined`**

- 原因 A：`FileInterceptor('file')` 的字段名和前端 FormData 的 key 不一致。
- 原因 B：前端 `Content-Type` 被手动设成了 `multipart/form-data`（丢了 boundary），或者 Body 类型根本没选 form-data。
- 原因 C：忘了加 `@UseInterceptors(FileInterceptor(...))`，Multer 压根没参与解析。
- 解决：三处逐一核对——前端 key、拦截器参数、装饰器是否存在。

**报错 3：`TS2339: Property 'filename' does not exist on type '{}'`**

- 原因：没装 `@types/multer`，或者参数没标注类型。
- 解决：`npm i @types/multer -D`，并把参数写成 `file: Express.Multer.File`。

**现象 4：上传成功但两个文件重名，前一个被覆盖**

- 原因：用 `originalname` 当文件名，用户传了两次同名文件。
- 解决：见 2.3 的命名策略表，改用时间戳 + 随机数或 UUID。

## 三、静态目录托管：让图片能被 URL 打开

### 3.1 为什么还需要这一步

文件已经写到 `dist/images/1662894316133.png` 了，但这时你访问 `http://localhost:3000/images/1662894316133.png` 会得到 **404**。

原因：NestJS 默认只处理"你注册过的路由"，`/images/xxx.png` 不对应任何 Controller 方法，自然找不到。磁盘上的文件 ≠ 可访问的 URL，中间还差一个"**静态资源托管**"的映射。

**大白话**：文件已经在仓库里了，但仓库没开对外窗口。`useStaticAssets` 就是去开这个窗口，并给窗口挂个门牌号（虚拟前缀）。

### 3.2 配置静态目录

```ts
// src/main.ts
import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { join } from 'path';
import { AppModule } from './app.module';

async function bootstrap() {
  // 关键：必须指定泛型 <NestExpressApplication>
  const app = await NestFactory.create<NestExpressApplication>(AppModule);

  // 把 images 目录托管为静态资源
  app.useStaticAssets(join(__dirname, 'images'), {
    prefix: '/xiaoman', // 虚拟前缀：URL 里必须带 /xiaoman 才能访问
  });

  await app.listen(3000);
}
bootstrap();
```

**`prefix` 是什么**：它是"门牌号"，只影响 URL，不影响磁盘位置。

| 配置 | 磁盘文件 | 访问 URL |
| --- | --- | --- |
| `prefix: '/xiaoman'` | `dist/images/1662894316133.png` | `http://localhost:3000/xiaoman/1662894316133.png` |
| 不配 `prefix` | 同上 | `http://localhost:3000/1662894316133.png` |
| `prefix: '/static/img'` | 同上 | `http://localhost:3000/static/img/1662894316133.png` |

### 3.3 `__dirname` 的秘密（本篇第二大坑）

为什么上传配置写 `join(__dirname, '../images')`，静态目录写 `join(__dirname, 'images')`，两个看着不一样，却指向同一个地方？

因为 **`__dirname` 指的是"当前 JS 文件所在目录"，而运行的是编译后的 `dist` 目录，不是你写的 `src` 目录**。

| 源文件 | 编译后位置 | `__dirname` 的值 | `join(__dirname, ...)` 结果 |
| --- | --- | --- | --- |
| `src/upload/upload.module.ts` | `dist/upload/upload.module.js` | `dist/upload` | `dist/upload/../images` → **`dist/images`** |
| `src/main.ts` | `dist/main.js` | `dist` | `dist/images` → **`dist/images`** |

对上了——**上传目录和静态目录必须是同一个物理位置**，否则会出现"上传成功但图片 404"的诡异现象。

> **更稳妥的写法**：用 `process.cwd()`（项目根目录）代替 `__dirname`，把图片存到项目根下的 `images/`，不受编译产物目录影响：
>
> ```ts
> // upload.module.ts
> destination: join(process.cwd(), 'images'),
> // main.ts
> app.useStaticAssets(join(process.cwd(), 'images'), { prefix: '/xiaoman' });
> ```
>
> 这样做的好处：`nest build` 若开启了 `deleteOutDir`（`nest new` 默认就是 `true`），会**清空整个 `dist` 目录**，你上传的图片会一起被删掉。放到 `dist` 外面的目录才安全。原文用 `__dirname` 是为了教学直观，实际项目建议 `process.cwd()`。

### 3.4 验证静态目录是否生效

1. 启动项目。
2. 用 Apifox 上传一张图，记下返回的 `url`（比如 `/xiaoman/1662894316133.png`）。
3. 浏览器直接打开 `http://localhost:3000/xiaoman/1662894316133.png`。
4. 能看到图片 = 配置成功；`Cannot GET /xiaoman/xxx.png` = 路径或目录没对上。

### 3.5 常见错误与排查

**报错 1：`TS2339: Property 'useStaticAssets' does not exist on type 'INestApplication<any>'`**

- 原因：`NestFactory.create(AppModule)` 没写泛型，返回的是通用的 `INestApplication`，这个类型上没有 `useStaticAssets`（它是 Express 平台特有的方法）。
- 解决：改成 `NestFactory.create<NestExpressApplication>(AppModule)`，并从 `@nestjs/platform-express` 导入 `NestExpressApplication`。

**现象 2：图片 404，且报 `Cannot GET /xiaoman/xxx.png`**

- 原因 A：`prefix` 和访问路径不一致（比如配了 `/xiaoman` 却访问 `/images/xxx.png`）。
- 原因 B：静态目录和上传目录不是同一个物理路径（见 3.3）。
- 原因 C：文件名拼错，或文件确实没落盘。
- 解决：先确认磁盘上文件确实存在，再核对两个 `join` 是否指向同一目录，最后核对 URL 前缀。

**现象 3：开发时图片正常，重新 `npm run build` 后全部 404**

- 原因：`dist` 被清空，连上传的图片一起删了。
- 解决：改用 `process.cwd()` 存到项目根目录下（见 3.3 的提示）。

## 四、文件下载

### 4.1 两种方式先对比

| 方式 | 核心 API | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- | --- |
| 直接下载 | `res.download(路径)` | 一行搞定，自动处理文件名和响应头 | 只能下单个已存在的文件，不易动态加工 | 下载单个文件 |
| 文件流 | `res.setHeader()` + `stream.pipe(res)` | 可以边处理边发（压缩、加密、拼接） | 要自己设响应头，代码更多 | 打包下载、大文件、需要加工 |

> 前置提醒：这两种方案都要注入 `@Res()`，而**注入 `@Res()` 后就等于宣布"响应由我自己负责"**，此时 `return` 的值会被忽略。这条坑 03 篇 2.8 节和 04 篇都踩过，这里第三次出现。

### 4.2 方式一：`res.download()` 直接下载

```ts
// src/upload/upload.controller.ts
import { Controller, Get, Post, Res, UseInterceptors, UploadedFile } from '@nestjs/common';
import { FileInterceptor } from '@nestjs/platform-express';
import type { Response } from 'express';
import { join } from 'path';

@Controller('upload')
export class UploadController {
  @Post('album')
  @UseInterceptors(FileInterceptor('file'))
  upload(@UploadedFile() file: Express.Multer.File) {
    return { url: `/xiaoman/${file.filename}` };
  }

  @Get('export')
  downLoad(@Res() res: Response) {
    // 真实项目里这个路径应该从数据库查出来，这里写死演示
    const url = join(__dirname, '../images/1662894316133.png');

    // 会自动设置 Content-Disposition: attachment，并让浏览器弹下载
    res.download(url);
  }
}
```

`res.download()` 帮你做了三件事：

1. 读文件、写响应流。
2. 设置 `Content-Disposition: attachment; filename="..."`，告诉浏览器"这是要下载的，别直接打开"。
3. 自动按文件后缀推断 `Content-Type`。

**加一句错误处理更稳**（文件不存在时 `res.download` 会进回调的 `err`，不处理就会变成 500 且看不出原因）：

```ts
@Get('export')
downLoad(@Res() res: Response) {
  const url = join(__dirname, '../images/1662894316133.png');

  res.download(url, (err) => {
    if (err) {
      // 文件不存在、没有读权限等
      res.status(404).send({ message: '文件不存在' });
    }
  });
}
```

### 4.3 方式二：文件流转 zip 下载

需求场景：用户点"下载全部图片"，后端把多张图**打成一个 zip** 发给浏览器。

NestJS 本身不做压缩，用第三方库 `compressing`：

```bash
npm install compressing
```

```ts
// src/upload/upload.controller.ts
import { Controller, Get, Res } from '@nestjs/common';
import type { Response } from 'express';
import { join } from 'path';
import { zip } from 'compressing';

@Controller('upload')
export class UploadController {
  @Get('stream')
  async down(@Res() res: Response) {
    // 要打包的文件路径（多文件时循环 addEntry 即可）
    const url = join(__dirname, '../images/1662894316133.png');

    // 1. 创建一个 zip 流
    const tarStream = new zip.Stream();
    // 2. 把文件加入压缩流（异步，要 await）
    await tarStream.addEntry(url);

    // 3. 告诉浏览器这是一段二进制流
    res.setHeader('Content-Type', 'application/octet-stream');
    // 4. 告诉浏览器要下载，文件名叫 xiaoman.zip
    res.setHeader('Content-Disposition', 'attachment; filename=xiaoman.zip');

    // 5. 把压缩流接到响应上，边压缩边发
    tarStream.pipe(res);
  }
}
```

**多个文件打包**只需要多调几次 `addEntry`：

```ts
const files = [
  join(__dirname, '../images/a.png'),
  join(__dirname, '../images/b.png'),
];
for (const f of files) {
  await tarStream.addEntry(f);
}
```

**两个响应头的作用**：

| 响应头 | 值 | 作用 |
| --- | --- | --- |
| `Content-Type` | `application/octet-stream` | 声明"这是未知的二进制流"，浏览器不会尝试打开，直接当文件处理 |
| `Content-Disposition` | `attachment; filename=xiaoman.zip` | `attachment` 表示下载附件；`filename` 是保存时的默认文件名 |

> 原文素材里写的是 `filename=xiaoman`（少了 `.zip`），下载下来会是个无后缀文件，系统难以识别。本篇补上扩展名。
>
> 如果要下载**中文文件名**，需用 `encodeURIComponent` 编码，否则部分浏览器会乱码：
> `attachment; filename*=UTF-8''${encodeURIComponent('学习笔记.zip')}`

### 4.4 前端接收文件流并触发下载

`<a href="...">` 直接下载只适合 GET 且无需携带鉴权头的场景。更通用的做法是 **fetch 拿到二进制 → 造一个 Blob → 用临时 `<a>` 触发下载**：

```ts
// 前端：接收流并下载
const useFetch = async (url: string) => {
  // 1. 把响应体读成二进制缓冲区
  const buffer = await fetch(url).then((res) => res.arrayBuffer());

  // 2. 包成 Blob（type 不写也行，因为要下载而不是预览）
  const blob = new Blob([buffer], {
    // type: 'image/png',   // 这里是 zip，所以不指定
  });

  // 3. 造一个临时 a 标签
  const a = document.createElement('a');
  a.href = URL.createObjectURL(blob); // 生成一个指向内存的临时地址
  a.download = 'xiaoman.zip'; // 保存的文件名
  a.click(); // 触发下载

  // 4. 释放内存（不释放会一直占着）
  URL.revokeObjectURL(a.href);
};

const download = () => {
  useFetch('http://localhost:3000/upload/stream');
};
```

**为什么不能直接 `window.open(url)`？** 因为 zip 是 `octet-stream`，浏览器会直接下载，看起来"能用"；但如果接口需要 `Authorization` 头，或者想改文件名，就必须走 fetch 这条路。

### 4.5 常见错误与排查

**报错 1：`Error: ENOENT: no such file or directory, stat 'D:\...\dist\images\xxx.png'`**

- 原因：`res.download` 的路径所指文件不存在。多半是文件名写死错了，或该文件已被清理。
- 解决：先确认磁盘上有这个文件；真实项目应从数据库查路径，而不是写死。

**现象 2：接口返回 200，但浏览器没弹下载，页面还是一片空白 / 控制台报 JSON 解析错误**

- 原因 A：用了 `res.download()` 但同时又 `return` 了数据，或者没注入 `@Res()` 而直接写了 `res.download`（`res` 未定义）。
- 原因 B：流式下载时忘了 `pipe`，请求会一直挂着直到超时。
- 解决：注入 `@Res() res: Response`，只保留 `res.download(url)` 或 `tarStream.pipe(res)`，**不要 return**。

**报错 3：`ERR_STREAM_PREMATURE_CLOSE` / 下载下来的 zip 打不开**

- 原因：`await tarStream.addEntry(url)` 没加 `await`，压缩流还没写完就开始发送了。
- 解决：`addEntry` 必须 `await`，尤其是打包多个文件时。

**现象 4：下载的文件名变成 `download` 或乱码**

- 原因：`Content-Disposition` 里的 `filename` 含中文未编码，或压根没设这个响应头。
- 解决：中文名用 `filename*=UTF-8''${encodeURIComponent(name)}`。

**现象 5：跨域前端拿不到 `Content-Disposition`，改不了文件名**

- 原因：浏览器默认只允许 JS 读取少数几个安全响应头。
- 解决：后端需要 `res.setHeader('Access-Control-Expose-Headers', 'Content-Disposition')`。
