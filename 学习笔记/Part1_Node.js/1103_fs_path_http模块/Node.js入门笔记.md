## 一、Node.js 是什么？

**一句话**：==Node.js== 是一个让 JavaScript 能在电脑（==服务器==）上运行的=="运行环境"==。

**通俗解释**：

- 以前 JavaScript 只能在浏览器里跑，负责网页上的点击、弹窗、动画这些"前台"工作。
- Node.js 基于谷歌的 Chrome V8 引擎，把 JavaScript 带出了浏览器，让它能像 Java、Python 一样在服务器端干活——读写文件、访问数据库、处理网络请求。
- 它的底层源码用 C++ 编写，2009 年由 Ryan Dahl 开发，如今被 Netflix、Uber、LinkedIn、PayPal 等大公司广泛使用。

**核心特点**：事件驱动、非阻塞 I/O、单线程处理高并发。

---

## 二、它是怎么工作的？（视频核心内容）

### 1. ==非阻塞（异步）架构==——Node.js 的工作方式

视频用**餐厅服务员**做比喻：

| | 服务员（线程）的做法 | 结果 |
| --- | --- | --- |
| **非阻塞（Node.js）** | 把菜单交给厨房后，继续去服务其他桌，不用等菜做好 | 一个人能同时服务很多桌 |
| **阻塞（传统框架）** | 守在厨房门口干等，这桌菜没上完就不接其他客人 | 客人多了就忙不过来 |

- 传统框架（ASP.NET、Rails 等）默认是阻塞式：一个请求占一个线程，查数据库时线程就闲着等结果；并发用户一多，线程耗尽，要么排队要么加硬件。
- Node.js 默认非阻塞：==**所有请求共用一个主线程**==，遇到数据库查询等耗时操作时不等待，立刻去处理下一个请求。

### 2. ==事件队列==——Node.js 的"待办清单"

```
请求到达 → 主线程处理 → 遇到耗时操作（查数据库/读文件）
        → 不等待，继续服务其他请求
        → 数据库准备好结果后，把消息放进"事件队列"
        → Node 在后台一直盯着事件队列，发现有事件就取出来处理
```

这就是 Node.js 单线程却能高效处理高并发的秘密。

### 3. 适用边界（重要）

- ✅ **适合**：数据密集型、实时应用（大量读写磁盘/网络）
- ❌ **不适合**：CPU 密集型应用（视频编码、图像处理、大量复杂计算）——因为计算会占住唯一的主线程，其他请求只能排队等待

**一句话总结**：==Node.js 用"单线程 + 事件队列"实现非阻塞 I/O，用更少的资源扛住更多请求；代价是 CPU 密集任务会卡住主线程，这类场景要避免。==

## 三、Node.js 能干什么？

| 用途 | 说明 | 常见例子 |
| --- | --- | --- |
| **后端 Web 服务** | 提供 API 接口，处理前端请求 | 电商系统的商品/订单接口 |
| 实时应用 | 双向通信，服务器主动推送消息 | 聊天软件、在线协作、游戏排行 |
| 命令行工具 | 写脚本、自动化任务 | 打包工具、代码检查工具 |
| 前端工程化 | 几乎所有前端构建工具都基于 Node | npm、webpack、Vite、TypeScript 编译器 |

配套的重要工具：
- ==**npm**：Node.js 自带的包管理器，用来安装和管理别人写好的模块（类似手机应用商店）==
- ==**nvm**：Node.js 版本管理工具，方便在多个版本之间切换==

## 四、适用于哪些场景？

**典型场景**
1. **==高并发==的==I/O==密集应用**：聊天室、消息推送、直播弹幕、实时协同
2. **==数据密集型==应用**：需要频繁读写数据库/文件的系统
3. **REST API 服务**：移动端/前端的后端接口（本实习项目就是这种）
4. **微服务架构**：按业务拆分成多个独立小服务
5. **工具链**：前端构建、脚手架工具

**不推荐的场景**
- 视频转码、图片处理、机器学习推理等 CPU 密集型任务
- 需要大量多线程并行计算的任务



# 五、Node.js和客户端JS的对比

Node.js和客户端JS（浏览器中运行的JavaScript）有以下几个主要区别：

1. 运行环境：**Node.js是在服务器端运行的JavaScript运行时环境，而客户端JS是在浏览器中运行的。**
2. I/O操作：Node.js采用了非阻塞I/O模型，可以高效地处理大量的I/O操作，如文件读写和网络请求。而客户端JS通常采用阻塞I/O模型，因为它主要处理用户界面相关的操作。
3. DOM访问：在客户端JS中，可以通过操作DOM（文档对象模型）来操作和改变网页的结构和内容。而在Node.js中，没有直接的DOM访问，因为它没有浏览器的窗口和文档对象。
4. 模块系统：Node.js使用CommonJS模块系统，可以方便地引入和使用模块。而现代客户端JS通常使用ES6模块系统，需要通过工具（如Webpack）进行打包和构建。
5. API访问：客户端JS可以通过浏览器提供的API访问各种功能，如操作DOM、进行AJAX请求、处理表单等。而Node.js提供了一些服务器端相关的API，如文件系统访问、网络通信、数据库连接等。

尽管Node.js和客户端JS有一些区别，但它们都是基于JavaScript的，开发者可以使用相似的语法和开发技巧来编写代码。



**==客户端和服务器端是什么==**     🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸🥸

**客户端（Client）**：<u>发起请求、面向用户的一侧。通常是用户设备上的软件</u>，比如浏览器、手机 App、桌面程序。它<u>负责展示界面、接收用户操作，并向服务器发请求。</u>

**服务器端（Server）**：<u>接收请求、处理业务、返回结果的一侧</u>。它通常运行在服务器机器、云主机、容器里，也可以在你本机跑一个本地服务。它<u>负责数据库访问、权限校验、业务逻辑、接口响应等。</u>

注意：**“客户端/服务器端”是角色，不是绝对某台机器。**
比如你本机启动一个 Node.js 服务，然后用浏览器访问 `localhost:3000`，这时浏览器是客户端，你本机的 Node.js 进程扮演服务器端。

举例：

- 你在 Edge 里打开网页：Edge 是客户端。
- 网页向 `https://example.com/api` 请求数据：`example.com` 后面的服务程序是服务器端。
- <u>服务器端可能是 Node.js、Java、Python、Go 等写的。</u>
