

# 一、模块化的基本概念

==模块只是一个代称，它就像是一块砖（内部封装了多段代码），哪里需要就往哪里搬==

API 也是模块



## 1.什么是模块化

- 模块化是指解决一个每杂问题时,**自顶向下**逐层把系统划分成若干模块的过程。对于整个系统来说,**模块是可组合、分解和更换的单元**。

- **编程领域中的模块化**,就是<u>遵守固定的规则</u>,把**一个大文件**拆成**独立并互相依赖的多个小模块**。

- 把代码进行模块化拆分的好处:
  - 提高了代码的**复用性**
  - 提高了代码的**可维护性**
  - 可以实现**按需加载**



## 2.模块化规范

**模块化规范**就是对代码进行模块化的拆分与组合时**,需要遵守的那些规则**。

例如：

- 使用什么样的语法格式来**引用模块**
- 在模块中使用什么样的语法格式**向外暴露成员**

**模块化规范的好处**:大家都遵守同样的模块化规范写代码,降低了沟通的成本,极大方便了各个模块之间的相互调用,
利人利己。

Node.js使用的模块系统主要有两种：==CommonJS和ESM（ES Modules）==

**CommonJS**是Node.js最早使用的模块系统,它使用**require和module.exports** 来导入和导出模块。

**ESM(ES Modules)**是标准化的JavaScript模块系统,它在Node.js 12及更高版本中得到了原生支持。ESM使用**import和export** 语法来导入和导出模块。

# 二、Node.js中的模块化



## 1. Node.js 中模块的分类



Node.js 中根据模块来源的不同,将模块分为了3大类,分别是:

- **内置模块**(内置模块是由Node.js官方提供的,例如fs、path、http等)

-  **自定义模块**(用户创建的每个.js文件,都是自定义模块)

- **第三方模块**(由第三方开发出来的模块,并非官方提供的内置模块,也不是用户创建的自定义模块,<u>使用前需要先下载</u>)



==**补充：API分类** 🥸🥸🥸🥸🥸🥸🥸==   此处的模块 即 API

1. **ECMAScript 内置API（语言本身）** Array、Promise、Symbol、Math、JSON 等，V8引擎实现，浏览器、Node都自带。
2. **运行环境原生API（环境自带）** 浏览器：DOM、BOM、fetch、setTimeout Node：fs、path、http、process 由浏览器内核 / Node 的libuv等底层提供，不属于ES规范。
3. **自定义API（自己封装）** 你自己写函数、类、模块，对外暴露方法，就是你自己的API。 比如你封装一个 `getUserInfo()`，其他代码调用它，这就是自定义API。

```js
// 自定义API
function getUserInfo(id) {
  return { id, name: "xxx" }
}
export { getUserInfo }
```

  4.**第三方API（npm包）** 别人写好发布到npm，你安装后引入使用。 比如 axios、lodash、mongoose、   nestjs 这些。 <u>本质上也是别人写好的**自定义代码封装**，只是打包上传到npm仓库共享。</u>

> 注意：npm包只是JS代码封装，底层最终还是依赖上面两类：ES内置API + 运行环境API（fs、http等）



## 2.加载模块

使用强大的require()方法,可以加载需要的内置模块、用户自定义模块、第三方模块进行使用。例如:

```javascript
//1. 加载内置的 fs 模块
const fs = require('fs')

// 2. 加载用户的自定义模块 PS：后缀名 .js 可以省略
const custom = require('/custom.js')

// 3. 加载第三方模块(需先下载，然后再使用)
const moment = require('moment')
```

==注意:使用require()方法加载其它模块时,**会执行被加载模块中的代码**。若是有打印内容，会直接输出==



## 3.Node.js中的模块作用域

- **模块作用域**：和函数作用域类似,**在自定义模块中定义的变量、方法等成员,只能在当前模块内被访问**,这种模块级别的访问限制,叫做模块作用域。

加载一个自定义模块，之后会得到一个空对象，无法访问被加载模块中的私有成员

- 模块作用域的好处：
  - 防止了全局变量污染的问题

### 4.2 module.exports 对象

- 在自定义模块中,可以使==用**module.exports对象**,将模块内的成员共享出去,供外界使用==。

- **外界用require()方法导入自定义模块时,得到的就是module.exports所指向的对象。**

在一个自定义模块中，默认情况下，module.exports是一个空对象,即module.exports = {}，所以当外界通过require()方法加载该模块时，返回的是一个空对象。

```javascript
// 在一个自定义模块中，默认情况下，module.exports是一个空对象,即module.exports = {}，所以当外界通过require()方法加载该模块时，返回的是一个空对象。

// 向 module.exports 对象上挂载 username 属性
module.exports.username = '张三'

// 向 module.exports 对象上挂载 sayHello 函数
module.exports.sayHello = function () {
  console.log('大家好，我是' + this.username)
}

const age = 18
module.exports.age = age
```

```javascript
// 在外界使用require 导入一个自定义模块的时候，得到的成员
// 就是 那个模块中，通过 module.exports 指向的对象。

const m = require('./04.自定义模块.js')  // 后缀可以省略
```

### 4.3 共享对象时的注意点

使用require()方法导入模块时,导入的结果**,永远以module.exports指向的⭐⭐对象⭐⭐为准**。  相当于一个变量，变量值等于最后一次赋值的值

```javascript

// 向 module.exports 对象上挂载 sayHello 函数
```

### 2.1 格式化时间的传统做法

1 创建格式化时间的自定义模块

4 从自定义模块中导出格式化时间的函数

```javascript
// 定义格式化时间的方法
function dateFormat (daStr) {
    const dt = new Date(daStr)

    const y = dt.getFullYear()
    const m = padZero(dt.getMonth() + 1)
    const d = padZero(dt.getDate())

    const h = dt.getHours()
    const mm = padZero(dt.getMinutes())
    const ss = padZero(dt.getSeconds())
    return `${y}-${m}-${d} ${h}:${mm}:${ss}`
}

// 定义补零的方法
function padZero (n) {
    return n < 10 ? '0' + n : n
}

module.exports = {
    dateFormat
}
```

# 四、模块的加载机制



## 1.优先从缓存中加载

**模块在第一次加载后会被缓存**。这也==意味着多次调用require()不会导致模块的代码被执行多次。==

注意:不论是内置模块、用户自定义模块、还是第三方模块,它们都会**优先从缓存中加载,从而提高模块的加载效率。**

```javascript
console.log('hello ')
```

```javascript
require('./12.验证模块的缓存加载机制.js')
require('./12.验证模块的缓存加载机制.js')
require('./12.验证模块的缓存加载机制.js')

// 只会 输出一行 hello 
// 模块在第一次加载后会被缓存。这也意味着多次调用require()不会导致模块的代码被执行多次。
```



## 2.内置模块的加载机制

**内置模块是由Node.js官方提供的模块,内置模块的加载优先级最高。**

例如,require('fs')始终返回内置的fs模块,即使在node_modules目录下有名字相同的包也叫做fs。



## 3.自定义模块的加载机制

使用**require()加载自定义模块**时,必须指定**以/或 .. /开头的路径标识符**。在加载自定义模块时,如果没有指定./或 .. /
这样的路径标识符,则node会把它当作内置模块或第三方模块进行加载。



同时,在使用require()导入自定义模块时,如果省略了文件的扩展名,则Node.js会按顺序分别尝试加载以下的文件:

1 按照确切的文件名进行加载

2 补全.js扩展名进行加载

3 补全.json扩展名进行加载

4 补全.node扩展名进行加载

5 加载失败,终端报错



## 4.第三方模块的加载机制

如果传递给require()的模块标识符不是一个内置模块,也没有以‘’或‘’开头,则Node.js会从当前模块的父
目录开始,尝试从/node_modules文件夹中加载第三方模块。

**如果没有找到对应的第三方模块,则移动到再上一层父目录中,进行加载,直到文件系统的根目录。**

例如,假设在'C:\Users\itheima\project\foo.js'文件里调用了require('tools'),则Node.js会按以下顺序查找:

C:\Users\itheima\project\node_modules\tools

C:\Users\itheima\node_modules\tools

C:\Users\node_modules\tools

C:\node modules\tools



## 5.目录作为模块

当把目录作为模块标识符,传递给require()进行加载的时候,有三种加载方式:

1 在被加载的目录下查找一个叫做package.json的文件,并寻找main属性,作为require()加载的入口

2 如果目录里没有package.json文件,或者main入口不存在或无法解析,则Node.js将会试图加载目录下的index.js文件。

3 如果以上两步都失败了,则Node.js会在终端打印错误消息,报告模块的缺失:Error: Cannot find module'xxx'
